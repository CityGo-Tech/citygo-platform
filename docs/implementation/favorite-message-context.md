# Из избранного — к исходному диалогу

Следующий Web-этап после трёх режимов ИИ: сохранённое сообщение можно открыть
вместе с предыдущей перепиской, даже если его уже нет среди последних 100
сообщений. Основа — экран [избранного в Figma](https://www.figma.com/design/6pAycf8MPlTyddwYPH6NEL/CityGo?node-id=65-5343)
и [сохранённые результаты](https://www.figma.com/design/6pAycf8MPlTyddwYPH6NEL/CityGo?node-id=6-28).
Используются существующие Card, Button, Manrope и токены CityGo, без новых
картинок и сторонней библиотеки интерфейса.

## Путь пользователя

1. В избранном нажать «Открыть в диалоге».
2. Увидеть выбранное сообщение с выделением и до 99 предыдущих реплик.
3. При необходимости загрузить раннюю историю или вернуться в избранное.
   Список, его позиция и черновик текущего разговора сохраняются.
4. «Открыть весь диалог» открывает последнюю часть исходного разговора.
   Продолжение доступно по прежним правилам; закрытая переписка остаётся
   доступной для чтения. Сам переход вопрос помощнику не отправляет.

Просмотр источника доступен для своих вопросов, ответов помощника и
сохранённого прерванного ответа. Только явная отправка из обычного диалога
может вызвать ИИ и списание.

## Границы чтения

Новый `GET /v1/conversations/:id/messages/:messageId/context` возвращает
существующий `ConversationMessagesPage`: до 100 видимых реплик включительно
до выбранной, по возрастанию исходного bigint ID, и курсор ранней страницы.
Числа не преобразуются в JavaScript `Number`. Следующие страницы читаются
прежним `GET /v1/conversations/:id/messages?before=…`.

Сервер проверяет активного владельца, временный пароль, принадлежность
диалога и наличие точного сообщения с ролью user/assistant. Для чужого,
несуществующего или служебного источника — одинаковый 404; администратор
не получает обхода владения. Клиент дополнительно проверяет ответ, владельца,
диалог и точное последнее сообщение. Поздние ответы после выхода или смены
источника отбрасываются; повтор загрузки возможен только по нажатию.

В памяти показаны до 1 000 последовательных сообщений. Загрузка более ранних
страниц вытесняет новые, сохраняя непрерывный участок; кнопка «К сохранённому
сообщению» повторно открывает исходное окно. Это ограничение экрана, не удаления
истории. SQL использует существующие индексы и ограниченную keyset-выдачу;
фиксированная стоимость чтения при росте базы не гарантируется.

## Совместимость

Новых миграций, таблиц, прав и провайдеров нет; схема остаётся 35.
Изменены только пользовательские подписи: «Режим работы», «Максимум»,
«Баланс», «Минимум». Цена не добавляется к названию «Минимума»; сам тариф
3 ₽ за успешный ответ и резерв 5 ₽ CityGo сохраняются. Для RouterAI остаётся
фактическая стоимость ×10. Маршрутизация, согласия, финансовые операции,
ЮKassa с чеками, телефон и подарок 500 ₽ не изменены.

Проверки включают HTTP/контракты/client, владельца и bigint-пагинацию в БД,
ограниченную роль и блокировку владельца в настоящем PostgreSQL, состояния
ресурса и сценарии desktop/mobile-web. Они используют вымышленные данные;
проверка не требует реальных AI-запросов, SMS, писем или платежей.
PR сам по себе не обновляет сервер и не включает автодеплой.
