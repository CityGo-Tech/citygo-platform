# CG-003 — изоляция состояния аккаунтов

Реализация 22 сентября 2026 в `citygo-platform-review`, отдельная ветка
`codex/session-isolation-cg003` от `5567464` (main после PR #29).
Исходная сверка и результаты CI main: [CG-001 / CG-002](baseline-2026-09-21.md).

## Что изменено

- Общий клиент получает сигнал срока жизни сессии. Logout, защищённый HTTP 401
  и обнаруженная смена владельца отменяют старые JSON/SSE-запросы; поздние ответы,
  ошибки и завершения старых операций не меняют новый экран. Ошибка пароля при
  входе не считается истечением другой сессии.
- Web очищает анкету, профиль, историю, черновики, согласия, уведомления,
  индикаторы занятости и маршрут. Состояние дочерних форм создаётся заново.
  Обновление того же аккаунта сохраняет текущий черновик.
- Вкладки передают только случайный сигнал очистки, без идентификаторов и данных.
  При возвращении в Web проверяется владелец серверной сессии; это также работает
  при отключённом localStorage. Admin очищает сводку и редактируемые настройки
  по сигналу, 401 и возвращению во вкладку; повторная загрузка явная.
- Expo очищает память сразу, затем последовательно удаляет credential из
  SecureStore и пытается отозвать серверную сессию. Очередь чтения/записи/удаления
  не позволяет задержавшейся записи входа восстановить token после logout.
  Перед новым входом удаляется и credential, оставшийся после неудачного восстановления.
  Ошибка удаления видна пользователю и блокирует вход до повторной очистки.
  На повтор сохраняются намерение отозвать исходную сессию и её credential только
  в памяти; после успешной локальной очистки credential забывается, даже если сервер
  недоступен. Повтор не подменяет пользовательский logout простым сообщением об expiry.
- Выход доступен во время чата. Отзыв на сервере имеет ограничение ожидания
  10 секунд; отсутствие подтверждения не выдаётся за успешный серверный выход.

Новых миграций, переменных окружения и зависимостей нет. Контракт API и ключ
SecureStore `citygo.session` сохранены. Провайдеры, модель RouterAI, бюджеты,
секреты и пользовательские базы не изменялись.

## Проверки

Локальные проверки используют вымышленные данные, без платных или живых LLM.

- Typecheck и lint затронутых пакетов Web, Admin, Expo, api-client — PASS.
- Тесты api-client — 12/12 PASS, включая поздние JSON/401, отмену зависшего SSE,
  гонки SecureStore, offline revoke и ошибку удаления credential.
- Production Web build — PASS; lint новых/изменённых E2E — PASS.
- Полный Playwright — 56/56 PASS: desktop и mobile-web Chromium. Добавлены
  A → logout → B, смена ID анкеты, 401 чата, задержавшийся ответ, сетевой сбой
  logout, межвкладочная очистка, focus с тем же/другим владельцем и Admin.
- Expo export Android + iOS — PASS. Это проверка сборки, **не device QA**.

Сохранены существующие предупреждения конфигурации Next ESLint; они не являются
ошибками сборки. Полный CI ветки должен быть зелёным перед merge. Тесты PostgreSQL
для ветки выполняются CI на отдельной тестовой БД, не на локальных данных владельца.

## Границы и ручная приёмка

- Web не может удалить HttpOnly cookie без ответа сервера. При неудачном logout
  данные текущего экрана скрыты, новый вход блокируется и доступен повтор выхода.
  Перезагрузка страницы при сохранившейся cookie может восстановить старую
  серверную сессию: не передавать устройство другому человеку до подтверждённого выхода.
- Abort и сброс клиентского состояния не отменяют уже принятую сервером команду
  и не возвращают ранее отправленные AI данные. Межвкладочный сигнал не является
  механизмом авторизации; права по-прежнему проверяет API.
- В Safari/WebKit и на реальных Android/iOS эта ветка ещё не проверена.
  На устройствах нужно пройти: вход A → черновики анкеты/чата → airplane mode →
  logout → перезапуск → вход B, а также 401 и выход во время streaming.
  Ожидание: нет данных A и сохранённого credential; offline не обещает server revoke.
- Ошибки/зависание и runtime-валидация остальных API/SSE-операций относятся к
  CG-004; отображение Expo XP/последнего квеста и разделение busy — CG-005.
