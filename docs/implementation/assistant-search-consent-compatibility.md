# Согласия при обновлении поисковой инструкции — 6 ноября 2026

От `main 5b9b077` подготовлена узкая совместимость после PR #183. Инструкция
`routerai-native-web-search-instructions-v2` уточняет дату и выбор действующих
официальных источников. Она не меняет получателей, состав передаваемых данных,
внешний поиск, транспорт, число результатов и правила оплаты.

## Найденный побочный эффект

Фабрика хеширует полный webSearch-профиль в policy ID, включая техническую
версию инструкции. Поэтому исходный PR #183 меняет Maximum и общий policy ID,
даже при неизменном тексте сведений об обработке. Этот ID входит в snapshot
регистрационного согласия. Без исправления действующий аккаунт получает
`SERVICE_CONSENT_REQUIRED` и не может пользоваться сервисом до нового выбора.

Это установлено через реальные фабрики до/после PR #183 и штатные функции
согласий с синтетическими SELECT-only данными. Сервер и реальные согласия
не изменялись. Переносить или записывать согласие за пользователя нельзя.

## Исправление

Чистый helper `webSearchConsentProfile` сохраняет точное v1-представление
только для известной пары инструкций v1/v2. Он используется исключительно
в вычислении consent policy ID. Все остальные поля профиля входят в хеш
без изменений; неизвестная будущая v3 не нормализуется.

Таким образом, прежние Maximum/global policy ID и точный snapshot/версия
регистрационного согласия остаются прежними. Сохранённые записи и выбор
пользователя не переписываются. Изменение текста сведений, получателей,
состава обработки или других параметров по-прежнему меняет policy и требует
штатного явного выбора. Это не общий обход новых условий и не нормализация
всех будущих инструкций.

Исполнение получает исходный полный профиль v2. Его отдельный execution key
и catalog ID меняются и требуют явного операторского переноса полного
правила бюджета. Сохранение согласия не даёт разрешения использовать новое
исполнение с прежним budget key. Ни автоматического rekey, ни повышения
потолков, ни сброса счётчиков нет.

## Проверки и будущий выпуск

Регрессия сравнивает настоящую фабрику с записанными идентификаторами старого
проверенного SHA `288cf966` на синтетическом уведомлении. Сверяются глобальная
и Maximum policy, версия и hash service snapshot. Отдельно проверяются
отличие нового execution/catalog, настоящий v2 и отказ исполнения с v1,
production gate с прежним policy ID и отказ с неверным, неизменность входного
объекта, новые версии и другие поля профиля.

Полные Linux CI и Container smoke привязываются к окончательному SHA этой
правки; результаты PR #183 не считаются новым прогоном. Новых миграций нет,
схема 49 и runtime v17. Три режима, RouterAI ×10 после завершённого ответа,
«Минимум» 3 ₽, отсутствие денежного удержания, чеки ЮKassa, телефон и подарок
500 ₽ сохраняются.

Сервер и автодеплой этим изменением не меняются. Для будущего выпуска нужно
заново вычислить точную пару budget descriptors на окончательном SHA:
первоначальная проекция PR #183 к нему не подходит. Прежний private policy ID
должен сохраниться; неизменность реального JSON проверяется свежо при подготовке
разрешённой операции. Старую несверенную попытку не переносят и не объявляют
бесплатной. Живое качество нового ответа этой регрессией не доказано.
