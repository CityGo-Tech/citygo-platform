# Аккаунты клиентов, воронка и записи посещений

Подготовлено 28 октября 2026 года поверх `main c1ffe2b`. Этот этап добавляет
наблюдение за пользовательским путём; он не меняет тарифы, резерв, оплату,
подтверждение контактов или выдачу подарка. Миграций нет: схема остаётся 36.
Публикация PR не означает обновление сервера или включение Метрики.

## Два источника

В админке super admin открывает список аккаунтов, ищет пользователя по email
или логину и выбирает карточку. Видны состояние аккаунта, баланс и резерв,
подтверждение контактов и подарок, профиль переезда, личный план, избранное,
диалоги с полными сохранёнными сообщениями и хронология действий.
Большие списки и история читаются страницами; это не ограничение всей истории.
Данные отображаются как текст. Вход от имени пользователя не выполняется.

Старая история восстанавливается только из действительно сохранённых записей.
Например, для плана видны дата создания и последнее сохранённое изменение;
промежуточные завершения и возвраты в работу задним числом не сочиняются.

Показатели регистрации, подтверждений, диалогов, успешных AI-ответов и оплат
рассчитываются сервером по записям CityGo. Воронка строится по когорте новых
аккаунтов за выбранные 1–90 дней: она не является отчётом обо всех посещениях
лендинга и не зависит от блокировщика Метрики. Клиентские клики сохраняются
отдельными событиями и не доказывают оплату, доставку SMS или ответ модели.

Яндекс.Метрика дополняет эти данные посещениями, переходами по интерфейсу,
картой кликов и Вебвизором. Нельзя обещать запись каждого посещения:
[Вебвизор записывает выборку и хранит записи 15 дней](https://yandex.ru/support/metrica/ru/webvisor/requirements).
Коды, сообщения и другие личные поля в записи скрыты. Их полный текст
доступен только в защищённой карточке CityGo, а не в Метрике.

## Доступ и связь с Метрикой

Все новые административные маршруты требуют действующую сессию **super admin**.
Роль, блокировка, отзыв сессии и требование смены пароля повторно проверяются
в транзакции. Обычная роль admin сохраняет прежнюю операционную сводку, но не
получает доступ к личной переписке. Каждый просмотр частной карточки или её
раздела создаёт запись аудита с действующим администратором, целью и числом
результатов; содержимое сообщений и контакты в аудит не копируются.

Обычные пользовательские маршруты по-прежнему проверяют владельца диалога.
Новые административные GET-маршруты не создают сессии пользователя и не дают
возможности писать от его имени, менять баланс или редактировать сообщения.

В Метрику передаётся только отдельный непрозрачный `cga_…` идентификатор,
полученный HMAC с отдельным назначением ключа. Email, телефон и внутренний ID
аккаунта не передаются. Такой же идентификатор виден в карточке администратора
для поиска посещений в Метрике. При отсутствии серверного ключа идентификатор
не выдаётся. Существующий ключ защиты телефона не изменяется.

## Границы записи

Метрика по умолчанию выключена. Включение задаётся тремя публичными параметрами
сборки Web, перечисленными в `.env.web.example`. Они разрешены только для Web
и сборки и не расширяют список приватных переменных API/worker.

Для приложения создан отдельный счётчик **113847047** —
**«CityGo — pilot.ситиго.рф»**, с адресом только `https://pilot.ситиго.рф`
и московским часовым поясом. Вебвизор включён; при выпуске запись всех полей
должна оставаться выключенной. Для этого счётчика используются 29 целей
`citygo_*` с точным совпадением идентификатора и отдельный дашборд приложения.
Прежний счётчик **105736701**, его цели и история сохранены; перенос старых
визитов и целей в новый счётчик не выполняется. Новый ID задаётся параметром
сборки Web. Создание и настройка счётчика не включают SDK в работающем приложении.

Счётчик допускается только на корневой странице утверждённых доменов CityGo.
Админка, отдельные страницы входа, восстановления и оплаты не загружают SDK.
Учтены DNT, GPC, локальное отключение и неизвестная роль/сессия. Страницы с
query/hash и переходы с неподходящим referrer исключены: это намеренно уменьшает
покрытие, включая часть рекламных переходов. Учёт доменных результатов CityGo
от этого не зависит.

Личный интерфейс скрыт классом `ym-hide-content` уже при серверном рендеринге.
В записи раскрываются только явно помеченные статические элементы навигации.
Содержимое ввода, переписка, динамические заголовки, контакты и план скрыты.
Произвольные URL, тексты и параметры событий не отправляются; допустимы только
фиксированные события и перечисления режима, помощника и раздела. Tag Manager,
ecommerce, автоматическая передача заголовка и отслеживание ссылок в SDK выключены.
Ошибки/блокировка аналитики не останавливают операции пользователя.

## Совместимость административной сводки ИИ

Читаемый каталог административного API допускает три текущих режима и отдельное
сохранённое исполнение прежнего «Баланса» — до четырёх исполнений. Это исправляет
чтение сводки при совместимости со старыми диалогами. Лимит трёх денежных правил,
существующие разрешения расходов, тарифы и резерв не меняются. Чтение каталога
не обращается к моделям и не резервирует или списывает баланс.

## Проверка перед выпуском

- Пройти полные локальные CI и Container smoke именно для нового SHA.
- Проверить super admin, обычного admin, пользователя, отзыв сессии и смену роли.
- Проверить чужой ID, пагинацию ранних сообщений, текст с HTML и смену выбранного
  аккаунта во время ответа API; данные прежней карточки не должны остаться.
- Проверить отсутствие SDK и сетевых обращений Метрики на `/admin`; убедиться,
  что маски присутствуют до первой загрузки SDK на публичном интерфейсе.
- Сопоставить события воронки с реальными серверными исходами на синтетических
  данных. Не выполнять настоящую оплату или AI-запрос только ради аналитики.
- Для будущей сборки с Метрикой отдельно закрепить counter ID, параметры сборки
  и образы; обычная сборка с выключенным счётчиком не доказывает боевой сборки.

Новые галочки не добавляются. Документированная информация о наблюдении размещена
на `/legal/analytics`; сохранённые версии регистрационных согласий не переписываются.
