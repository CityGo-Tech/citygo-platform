# CG-006 — окружение и секреты по сервисам

Ветка `codex/service-env-cg006` от `15e5e97c` (main после PR #32).
Рабочая копия — только `citygo-platform-review`. Дата: 22 сентября 2026.
Предыдущий инкремент: [CG-005](cg-005-mobile-completion.md).

## Что изменено

- Убрана глобальная передача DB/AI-переменных через Turbo. Тестовая DB передаётся
  только API integration-test задаче. Секретный `.env` не является глобальным
  cache input; несекретный Web route и `.env.web` входят в cache key Web.
- Добавлен явный allowlist для каждого процесса. Web/build/mobile не получают
  DB/LLM credentials; API получает только известные ему настройки; worker и
  migrator — только DB-настройки. Неизвестные переменные не наследуются.
- `dev/start` разделяют API/Web процессы; сборка и миграции получают отдельные
  окружения. Сигналы завершают только созданные этим запуском процессы, без
  поиска/остановки чужих приложений по имени или порту.
- Корневой `.env` совместим для API/DB. Новые настройки можно разделить на
  `.env.api`, `.env.web`, `.env.mobile`, `.env.worker`, `.env.migrator`.
  Примеры и порядок приоритетов описаны в [runbook](../runbooks/service-environments.md).
- Мигратор больше не подгружает dotenv повторно; удалена ненужная зависимость.
  Worker больше не читает общую API/AI-конфигурацию и по-прежнему запрещает PGlite.
- Web отказывается запускаться с автоматическими app-local `.env*` файлами,
  не удаляя их; Expo dotenv отключён. Окружение тестов не читает runtime-файлы.
- CI использует вымышленные ключи-маркеры и проверяет их отсутствие в Web/mobile
  артефактах после сборок. Настоящие ключи в CI не добавлялись.

## Проверки и ограничения

- **17/17** новых тестов изоляции: allowlists, precedence, legacy/API DB fallback,
  относительные пути, отсутствие мутации исходного env, app-local dotenv guard,
  рассинхронизация API schema/allowlist, конфигурация Turbo, реальные дочерние
  процессы, остановка/ошибки и маршрут стадий `dev/start/migrate` со стабами.
- Локально прошли lint, полный typecheck и набор workspace-тестов; данные
  интеграционных тестов локально — PGlite в памяти, не пользовательские базы.
- Сборка API/worker и **4/4 startup-теста**, в том числе независимость worker от
  API/AI-конфигурации, прошли. Loopback-проверка использует закрытый порт 1 и
  вымышленные credentials, не реальное PostgreSQL-подключение.
- Expo Android/iOS export прошёл. Полный Web build/E2E и PostgreSQL 17 выполняет
  GitHub CI; итоговая ссылка и результаты фиксируются в PR. Локальный запущенный
  Web не пересобирался и не перезапускался.

Это защита от случайного наследования окружения, не sandbox от вредоносного кода
с доступом к файловой системе. Raw-команды вне scoped launchers и production
права secret store/контейнеров требуют отдельной настройки. Роли PostgreSQL не
созданы; локальный DB fallback обеспечивает совместимость, а не права доступа.

Реальные `.env`, ключи, базы, настройки моделей/лимитов и Supabase не менялись.
Реальных AI-запросов и deployment не было. Старые рабочие копии не затронуты.
