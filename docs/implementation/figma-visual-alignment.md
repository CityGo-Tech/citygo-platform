# Визуальное выравнивание Web с прототипом CityGo

Интерфейс Web приводится к [прототипу CityGo в Figma](https://www.figma.com/design/6pAycf8MPlTyddwYPH6NEL?node-id=6-3).
Основа изменения — `main 65e5278`, схема **44**, runtime v13. Результат этого
этапа — отдельный PR с единым оформлением и работающей навигацией. Слияние,
обновление сервера и включение автодеплоя в него не входят.

Общие компоненты `@citygo/ui-web`, локальный Manrope и существующие токены
сохранены; оформление нового каркаса ограничено `.prototype-shell`.
Административные страницы и правовые документы не перерабатываются.

из текущего API. Не реализованные возможности прототипа не активируются
визуальной кнопкой: Bubble остаётся обозначенным как будущий помощник.

## Каркас и навигация

На desktop используется единая верхняя навигация, компактный точный баланс и
меню аккаунта. В рабочем пространстве находятся тематическая колонка, основной
экран и карточка выбранного помощника. Кошелёк, телефон, избранное и чеки
используют тот же каркас. Заголовки, карточки и отступы согласованы с прототипом.

На узком экране остаются четыре пункта: план, диалоги, помощники и профиль.
Результаты доступны из карточки «Полезные результаты» в профиле. История чата
прокручивается отдельно; редактор и отправка располагаются над нижней
навигацией. Действия поиска и выгрузки диалога и дополнительные действия
сообщения остаются доступны через раскрываемые меню.

Прежняя карта квестов доступна из меню аккаунта только при наличии старого
профиля и совместимого выбранного диалога без `assistantKey`. Это не
переинтерпретирует историю специализированного помощника как старый квест.
Внешний переход в рабочую вкладку обрабатывается однократно: его намерение
не должно повторяться после открытия исходного диалога из избранного.

## Локальные assets

Исходные файлы Figma сохранены в `apps/web/public/figma`; временные адреса
выгрузки не используются в приложении. `assistant-portrait.ts` выбирает
оригинальные портреты для всех пяти существующих помощников. Логотип CityGo,
значок закладки и стрелка выбора также используют локальные оригиналы.

Bubble собирается компонентом `BubbleAvatar` из трёх неизменённых исходников:

| Файл                         | Исходная геометрия    | Положение в аватаре                                      |
| ---------------------------- | --------------------- | -------------------------------------------------------- |
| `bubble-gradient.png`        | PNG 128 × 128         | Отображение 64 × 64                                      |
| `bubble-highlight.svg`       | SVG 26.6827 × 17.7227 | Верхний блик с исходным выносом фильтра и поворотом −25° |
| `bubble-small-highlight.svg` | SVG 8.864 × 8.864     | Малый блик с исходным выносом фильтра                    |

Общая рамка аватара — 64 × 64. Корневые размеры SVG сохраняются, векторные
пути не перерисовываются и не подменяются похожим знаком. При проверке
метаданных читались только корневые размеры SVG; файлы не редактировались.

## Сохранённые рабочие сценарии

Новых API, контрактов, миграций и изменений runtime или workflows нет.
Существующие обработчики и серверная проверка операций сохраняются:

- три режима ИИ, резерв 5 ₽ CityGo, фактическая стоимость RouterAI ×10 и
  3 ₽ за успешный ответ режима «Минимум»;
- прежний магазин ЮKassa с чеками, создание и восстановление платежа;
- подтверждение email и телефона, однократный подарок 500 ₽;
- принадлежность сессии, диалога и черновика, отмена и проверки `busy`;
- избранное, история, поиск, TXT-выгрузки и действия личного плана;
- маскирование контактов и переписки в Метрике, запрет записи нажатий
  клавиш в пользовательских полях.

Реальные провайдерские вызовы для этой разработки не выполняются. Браузерные
фикстуры используют вымышленные данные, перехватывают API, блокируют внешние
адреса и отклоняют денежные, email, SMS и AI-операции.

В тестах API пройдены **649** случаев и пропущены **4**, в тестах БД пройдены
**486** и пропущены **99**. Все эти **103** пропуска относятся к проверкам,
которым нужен явно выделенный PostgreSQL в `TEST_DATABASE_URL`; переменная
в этом прогоне не задана. Поэтому этот результат не подтверждает реальные
PostgreSQL-блокировки, гонки и права отдельных подключений. Дополнительно в
`test:env` пропущен один Linux-only тест передачи сигналов, поскольку прогон
выполнен в Windows.

Это завершённый `pnpm check`, но не отдельный релизный Linux/Docker-прогон
13 свежих команд и не запуск Docker Container smoke. Последние изменения
ещё требуют итогового браузерного подтверждения. Проверки новой навигации
отдельно покрывают одноразовые переходы, открытие диалога из избранного и
доступность старой карты.

Рабочий сервер этим PR не обновляется; автодеплой остаётся выключенным.
