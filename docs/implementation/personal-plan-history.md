# Сохранённые версии шага «Мой план»

Figma: файл `6pAycf8MPlTyddwYPH6NEL`, узел `6:25` («План учитывает уточнение»). Кнопка «Что изменилось» открывает сравнение текущей и выбранной сохранённой версии в существующей оболочке CityGo. Использованы действующие Card/Button, Manrope, токены, скругления и адаптивные карточки. Прототипные тексты заменены реальными данными пользователя. Шапка, логотип и изображения помощников не меняются.

Миграция `0041_personal_plan_history.sql` добавляет `personal_plan_item_history` без новой последовательности. Для существующих живых шагов сохраняется только их фактическое текущее состояние с признаком начала истории. Прежние версии не восстанавливаются и не выдумываются. Новые версии сохраняют точные название, описание, статус и чек-лист после явных действий пользователя; автоматическое изменение плана, AI и откат версии отсутствуют.

Запись версии входит в ту же транзакцию, что create/edit/status/checklist, после итогового изменения чек-листа. Блокировка текущего пользователя и CAS родительского шага сохранены. Повтор create возвращает существующий результат без новой версии, конфликт и ошибка записи истории откатывают изменение. SQL-триггер разрешает только снимок текущего живого шага активного владельца. Идентичность истории неизменна. API-роль получает SELECT и INSERT только шести полей снимка; UPDATE/DELETE, подстановка времени и начального маркера запрещены. Worker не получает доступа.

`GET /v1/personal-plan/:id/history?before=<revision>` возвращает только собственный живой шаг, максимум пять версий и 256 КиБ JSON массива за страницу. Составной PK `(item_id,revision)` обслуживает обратную keyset-пагинацию. ID остаются строками bigint, версии — безопасными целыми. Возврат после чтения повторно проверяет сессию; ответ `no-store`. История блокированного аккаунта, аккаунта с временным паролем или удалённого/чужого источника недоступна.

Удаление сохраняет существующую семантику плана: обычный DELETE API — tombstone, после которого ни текущий шаг, ни сохранённые версии не выдаются. Содержимое остаётся в закрытой базе на тех же условиях хранения, что ранее сам soft-deleted шаг; это не стирание данных. Привилегированное физическое удаление владельца или источника удаляет родителя и историю по FK cascade. Прямое удаление истории при существующем родителе запрещено.

Клиент держит только одну ограниченную страницу и текущую версию сравнения. Смена владельца, abort, закрытие и ошибка прав очищают данные. При изменении текущей ревизии во время пагинации нужно обновить историю: версии разных состояний не смешиваются. Весь блок закрыт `ym-hide-content`; тексты/поиск/версии не пишутся в URL, storage, аналитику. Кнопки доступны клавиатурой, фокус возвращается в план, мобильная раскладка одна колонка. Просмотр не вызывает изменений, AI, SMS или платежей.

Проверки: контракты, API-client и состояние, PGlite create/edit/checklist/status/replay/CAS/rollback/privacy/cursors/bytes, upgrade40→41, HTTP и браузерные сценарии desktop/mobile. PostgreSQL opt-in `personal-plan.pg.test.ts` использует только явно заданную одноразовую локальную БД и проверяет настоящие grants, параллельные replay/CAS, Worker denial, чек-листы и каскад. Полный интеграционный релизный прогон выполняется отдельно для общей ветки.

Режимы AI, резерв 5 ₽ CityGo, тарифы, платежи/чеки ЮKassa, телефон/подарок и автодеплой не меняются.
