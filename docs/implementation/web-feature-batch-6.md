## Данные и совместимость

0041 добавляет personal_plan_item_history. Начальный снимок фиксирует реальное
состояние живого шага; прежние отсутствующие версии не восстанавливаются.
Изменения названия, описания, статуса и чек-листа записываются атомарно с шагом.
Удалённый шаг не раскрывает старые версии через историю. Существующее физическое
удаление родителя сохраняет каскад, обычное удаление шага сохраняет закрытые данные.

0042 добавляет human_support_reads. Курсор принадлежит пользователю и обращению,
двигается только вперёд и подтверждает реально показанный набор ответов.
Новые ответы после показанного набора остаются непрочитанными. Прежние ответы
не получают фиктивной отметки прочтения. Возможность уведомлений передаётся через
совместимое необязательное поле dashboard; старый API не вызывает лишний polling.
Переход к старому обращению и последующая пагинация объединяют идентичные записи.

0043 добавляет только два индекса истории баланса. API выбирает законченные
пользовательские операции до фильтрации и пагинации; технические удержания
не вытесняют их. Возврат появляется один раз, после подтверждённого списания
средств CityGo. Суммы сохраняют микрорублёвую точность.

Результат перечитывается при открытии и перед добавлением в черновик.
Изменение требует повторной проверки, удалённый/чужой результат недоступен.
Длинный исходник виден целиком; пользователь сам выбирает фрагмент до 4000
символов. Существующий черновик не обрезается и не перезаписывается.

Приватные тексты скрыты от Метрики, не попадают в URL и до подтверждения остаются
в памяти формы. После явного добавления текст следует существующей политике
черновиков вкладки. Смена аккаунта/сессии закрывает устаревшие формы.
Новых согласий и технических пояснений о провайдерах в интерфейсе не добавлено.

## Проверки и выпуск

Целевые проверки включают contracts/client/state/API/PGlite, настоящий
одноразовый PostgreSQL, права API/Worker, конкурентные операции и desktop/mobile.
Объединённый SHA дополнительно проверяется всеми семью локальными CI-командами
и шестью Container smoke-командами с сохранением прежних regression gates.
Старые результаты, статусы GitHub и образы не подменяются.

Служебные reset/restart inventories явно сохраняют новые таблицы; исторические
upgrade-репетиции до схемы43 проверяют откат поздней ошибки прав и сохранность данных.
База рабочего сервера, ключи, приём платежей, чеки и настройки провайдеров
не используются этими проверками. Публикация образов, слияние и выпуск требуют
отдельного следующего шага; автодеплой не включается.
