# Избранные сообщения — Web-инкремент

Подготовлено 20 октября 2026 в отдельной ветке `codex/message-favorites`,
поверх `e9daf2a` (draft PR #100). Это локальная реализация, не установленная
на рабочем сервере. Настройка Hyper-V CI остановлена по просьбе владельца;
её незавершённость не объявлена успешным CI и не снимает защиту выпуска.

## Что получает пользователь

Под сохранёнными сообщениями пользователя и ответами помощника есть кнопка
«В избранное». Повторное нажатие снимает закладку. Раздел «Избранное» доступен
из шапки и профиля. Он показывает полный текст, автора и отметку прерванного
ответа, поддерживает загрузку следующих страниц и удаление закладки.

Закладка сохраняется на сервере и переживает перезагрузку страницы/повторный
вход. Удаление закладки не удаляет сообщение. Черновики, поток незаконченного
ответа и приветствие интерфейса не выдаются за сохранённые сообщения.
Ни создание, ни чтение закладки не вызывает модель/Bubble, не списывает баланс,
не создаёт НПД-обязательства и не превращает переписку в общую базу знаний.

Сверены новый центральный блок и пустое состояние
[Figma 65:5343](https://www.figma.com/design/6pAycf8MPlTyddwYPH6NEL/CityGo?node-id=65-5343).
Использованы существующие Manrope, Card/Button, безопасный renderer ответов и
токены CityGo. Окружающая навигация приложения не объявляется полным переносом
прототипа. Это адаптивный Web, а не новый нативный экран Expo.

## Хранение и API

Закладка — булевый `messages.metadata.citygoFavorite`, без копии текста и без
новой таблицы/миграции. Удаление исходного сообщения удаляет и закладку; срок
хранения исходной переписки не продлевается. Остальные metadata, статус,
модельная квитанция, содержимое и финансовые связи не меняются.

- `POST /v1/messages/:id/favorite` с `{ "saved": true | false }` устанавливает
  явное состояние, а не переключатель. Повтор команды безопасен.
- `GET /v1/messages/favorites?before=<messageId>` читает до 20 своих сообщений,
  с дополнительным ограничением размера страницы. `nextBefore` — курсор
  следующей страницы. Порядок — от новых **сообщений** к старым, не дата закладки.
- Dashboard возвращает необязательный булевый `favorite` у сообщения; старые
  ответы/клиенты совместимы. Поле не добавляется в контекст внешней модели.

Владелец берётся только из проверенной сессии. Чужой/отсутствующий ID и
system/tool-сообщения дают одинаковый 404. Административная роль не расширяет
доступ. Ввод не принимает owner/content/metadata, ID проверяется как точное
положительное bigint без округления JavaScript. Сохранены same-origin,
no-store, парольный gate и запрет заблокированных/отозванных сессий.
Поздний ответ после выхода не публикуется, ответ с чужим `userId` не показывается.

Нужен обновлённый `deploy/postgres/grants.sql`: API получает **только**
`UPDATE(metadata)` для messages, не UPDATE текста/роли/владельца и не DELETE.
Worker не получает доступа. Новые права применяются штатным guarded release,
а не ручной командой на рабочей БД. Без них чтение работает, запись отказывает;
это не повод расширять роль до владельца таблиц или superuser.

Для пилота используются существующие индексы owner/thread/message.
Лимит выдачи не означает фиксированного числа просматриваемых SQL-строк:
перед ростом объёма нужен EXPLAIN на реалистичной выборке и отдельное решение
о частичном индексе/таблице закладок. Общая видимость сообщений, шаринг и
бессрочное архивирование не добавлены.

## Проверка

Новые контракты/SQL/HTTP/client тестируют владельца, запрет подмены,
идемпотентность, сохранение metadata, пагинацию, удаление источника и отсутствие
денежных/модельных операций. Отдельный настоящий PostgreSQL 17 проверяет
действующие column grants и параллельные обновления metadata. Одноразовый
loopback-only Docker-контейнер с синтетическими данными после проверки удалён.

Playwright на desktop/mobile-web проверяет регистрацию → тестовый разговор →
сохранение обеих ролей → reload → кабинет → удаление закладок с сохранением
переписки, а также поздний ответ после logout. Реальных AI-запросов, платежей,
серверных изменений, выпуска или новых ключей эта приёмка не включает.
