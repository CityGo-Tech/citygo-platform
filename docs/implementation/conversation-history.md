# Ранняя история разговоров

Подготовка от **24 октября 2026** поверх разговорного Web-прототипа.
Это разработка кода, **не серверный выпуск**. Телефон/ProstoSMS не нужны для
этого сценария и этим изменением не активируются. Автодеплой выключен.

## Пользовательский результат

В разговоре с помощником можно явно загрузить сообщения старше последних 100.
Более ранние сообщения добавляются перед уже видимыми, в числовом порядке
ID — не по времени, роли или порядку завершения сетевых запросов. Открытие
истории бесплатно: не вызывает модель, не создаёт сообщения и не списывает
баланс. Старые общий и закрытые разговоры также доступны только владельцу.

Загрузка не является анкетой и не меняет помощника. Выбор раннего сообщения
для избранного работает с исходным сообщением, без его копирования. Ошибка
страницы не удаляет уже показанную переписку; повтор чтения — явное действие.
Смена аккаунта/разговора отменяет устаревшие продолжения. История и её курсоры
не записываются в браузерное хранилище; после перезагрузки снова загружается
актуальная последняя страница.

Чтобы не накапливать в DOM всю переписку, окно просмотра ограничено по числу
страниц. Это **не запрет читать более ранние сообщения**: при продолжении
загрузки окно сдвигается к началу разговора. В таком режиме показано уведомление
о ранней истории, отправка нового вопроса недоступна до нажатия «К последним
сообщениям». Черновик вопроса при просмотре не теряется. Ограничение окна Web
не является новым лимитом контекста AI.

## Новый контракт

`GET /v1/conversations/:id/messages?before=<messageId>`

Ответ: `{ userId, threadId, messages, nextCursor }`.

- Без `before` возвращаются последние 100 видимых сообщений.
- С `before` — до 100 сообщений строго раньше указанного сообщения.
  Граница принадлежит тому же доступному разговору; чужой, отсутствующий
  или скрытый system/tool курсор не открывает переписку.
- Сообщения внутри страницы идут от старых к новым; ID — положительные
  строки PostgreSQL bigint, включая значения выше `2^53`. Не превращаем их
  в JavaScript Number.
- `nextCursor` равен первому ID страницы только при наличии ещё более ранних
  сообщений; иначе `null`. Курсор не является разрешением на чужой разговор.
- Параметры запроса проверяются строго; owner и выбранный thread сверяются
  также клиентом. Роль администратора не даёт права читать чужой разговор.

DB-reader отдельный от прежнего `history()`: keyset-фильтр по ID, максимум
101 строка для определения следующей страницы, короткая транзакция и порядок
блокировок user → thread. OFFSET и неограниченной выдачи нет. Новый индекс или
миграция этим срезом не добавляются; постоянное время чтения не обещается —
существующий индекс `(thread_id, created_at, id)` не равен `(thread_id, id)`.

Прежние detail/dashboard ответы, чтение Expo и построение контекста для AI
не переопределяются. Число загруженных страниц Web не ограничивает и не
расширяет контекст, передаваемый модели. Резерв **5 ₽ CityGo**, фактическая
стоимость **×10**, магазин, пополнения, возвраты и чеки ЮKassa сохраняются.

## Проверки подготовки

- Совместный целевой прогон contracts/DB/API/client и регрессий разговоров,
  избранного и тарифа: **38/38 PASS**, без пропусков. HTTP-проверки сравнивают
  все 60 публичных таблиц и 19 последовательностей до/после чтения, включая
  финансовые записи; нет DML или вызовов модели.
- Настоящий одноразовый PostgreSQL: **1/1 PASS**. На 260 видимых сообщениях
  проверены существующие runtime-права, точные bigint ID, закрытый разговор,
  чужие/скрытые курсоры, неизменность строк/последовательностей и ожидание
  блокировки владельца с повторной проверкой его статуса. Тестовые БД, роли
  и контейнер удалены адресно.
- Web: **64/64 unit**, включая 12 новых; **14/14 desktop/mobile E2E**,
  без пропусков и автоматических повторов. Проверены несколько страниц,
  прокрутка и сохранение последнего вопроса, reload, избранное раннего
  сообщения, подтверждённая закладка при ошибке последующего обновления,
  поздние ответы, чужой owner и смена сессии.
- Дополнительно **58/58** прежних desktop/mobile E2E разговоров, сессий,
  недостаточного баланса и телефонной формы — без пропусков и повторов.
  Всего выполнено 72 выбранных браузерных проверки; это не весь E2E-набор
  и не полный релизный прогон.
- Сценарий 1 250 сообщений подтверждает, что ограниченное окно не запрещает
  дойти до начала; старый просмотр read-only, возврат сохраняет черновик.
- TypeScript для contracts/DB/API/client/Web, scoped lint, форматирование и
  diff-check пройдены. Скриншоты управления историей просмотрены на desktop
  и mobile-web; временный Web-сервер остановлен.

Первоначальный браузерный прогон выявил отдельные проблемы тестовой геометрии
и локатора, а также смещение при исчезновении кнопки на последней странице.
Сохранены неуспешные результаты; после исправления добавлен честный статус
начала диалога и выполнен свежий успешный прогон. Старый failed не подменяется
успешным. Наличие документа не заменяет тесты и не разрешает серверную поставку.

Перед будущим выпуском нужны полный прогон точного SHA и отдельный безопасный
порядок поставки. Старые проверки PR #110/#111 не считаются проверками нового
кода. Реальные AI-запросы, платежи, SMS и рабочие данные в локальных тестах
не используются.
