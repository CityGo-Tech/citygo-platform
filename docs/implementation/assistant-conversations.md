# Отдельные разговоры с помощниками CityGo

Подготовлено 22 октября 2026 в ветке `codex/assistant-conversations` поверх
`main` после слияния PR #101. Это изменение исходного кода, **не обновление
сервера**. Полная приёмка точного коммита, PR и поставка — отдельные действия.
Автодеплой не включается; прежний магазин и чеки ЮKassa сохраняются.

## Что получает человек

В каталоге можно открыть разговор с координатором, помощником по жилью,
по работе, по резюме или гидом по городской жизни. У каждого — своя история.
Повторное открытие продолжает существующий активный разговор с этим помощником,
а не создаёт новую копию. Разговоры разных пользователей также не смешиваются.

Карточка больше не подставляет за пользователя вопрос. Открытие бесплатно:
модель вызывается только после отдельной отправки сообщения, при действующем
согласии и достаточном балансе. Сохраняются резерв **5 ₽ CityGo**, расчёт по
подтверждённой фактической стоимости **×10** и прежние проверки денежных рисков.
Выбор помощника не выбирает другую модель, не даёт бесплатный запрос и не
снимает незавершённый резерв другого разговора.

Список показывает реальные сохранённые разговоры и небольшой фрагмент
последнего сообщения. Можно открыть историю закрытого разговора, но отправка
в него запрещена. Управление закрытием/архивированием в этот срез не входит.
Старый общий разговор доступен отдельно, со всеми прежними сообщениями.
Избранное продолжает ссылаться на исходные сообщения, без переноса/копирования.

Bubble показан с партнёрским логотипом и недоступным действием: его API ещё нет,
поэтому сообщения и история партнёру не передаются. Приветствие экрана не
выдаётся за уже полученный ответ модели.

Web хранит только несекретный ID выбранного разговора, отдельно для каждого
владельца. Отключённое browser storage не блокирует работу. Черновики не
переносятся между разговорами; при смене владельца состояние и текущий поток
очищаются. Выбор фиксируется после успешного авторизованного чтения истории,
не после одного лишь создания разговора.

## Контракты и API

| Команда                                       | Результат                                                             |
| --------------------------------------------- | --------------------------------------------------------------------- |
| `POST /v1/conversations/start` с `{}`         | Прежнее поведение: открыть/продолжить общий разговор                  |
| Тот же endpoint с `{ "agentKey": "housing" }` | Открыть/продолжить свой разговор с указанным помощником               |
| `GET /v1/conversations?before=<id>`           | До 20 своих разговоров и `nextCursor` для следующей страницы          |
| `GET /v1/conversations/:id`                   | Заголовок и последние 100 сообщений выбранного собственного разговора |

Допустимы только пять ключей CityGo: `support`, `housing`, `job-search`,
`resume-builder`, `digital-mentor`. Bubble, provider/model и подставной owner
не становятся выбором помощника. Отсутствующий/чужой ID даёт одинаковый 404;
роль администратора не расширяет доступ к чужой переписке.

ID — точная положительная строка PostgreSQL bigint, включая значения выше
`2^53`, без преобразования в JavaScript Number. Страницы идут по ID от новых
к старым, не по времени последнего ответа; OFFSET и неограниченная выдача
не используются. `preview` ограничен 240 UTF-16 единицами без разрыва Unicode
символа; system/tool сообщения не включаются.

Новые list/detail ответы обязательно содержат `userId` текущего владельца.
Web сверяет его с владельцем открытого кабинета: валидный поздний ответ другой
сессии не должен попасть в чужой экран. Клиент также проверяет точный ID
запрошенного разговора, порядок страницы и курсор.

Поля `assistantKey` и `closed` в dashboard добавлены как необязательные для
совместимости со старыми ответами. Новый detail endpoint возвращает их явно:
`assistantKey=null` обозначает прежний общий диалог. Старый Expo продолжает
работать с общим диалогом; его новый каталог/список здесь не реализованы.

## Хранение и переход 24 → 25

Миграция [0025_assistant_conversations.sql](../../packages/db/migrations/0025_assistant_conversations.sql)
добавляет nullable `agent_threads.conversation_agent_key`. У всех существующих
строк остаётся `NULL`: нет backfill, удаления, перемещения сообщений, сброса
lease или изменения финансовых ссылок.

- Прежний уникальный индекс ограничивает только активный общий разговор.
- Отдельный частичный уникальный индекс допускает один активный разговор
  `(user_id, conversation_agent_key)` на помощника.
- CHECK требует совпадения выбранного помощника и фактической роли; trigger
  запрещает перепривязать закреплённый разговор, в том числе парной правкой
  обоих полей или после закрытия.
- Создание берёт блокировку пользователя до блокировки разговора. Повторные
  и одновременные открытия одного помощника получают тот же активный ID.
- Dashboard и прежний жилищный `quest start` продолжают работать только с
  общим разговором. Новый каталог не подменяет и не переписывает старый путь.

Правки grants, платёжной схемы, тарифного расчёта, runtime-конфига и AI-политики
не добавляются. Выпуск с миграцией требует штатных проверок и отдельного
решения; запуск тестов или слияние PR не применяет её на сервере.

## Что не входит в срез

| Возможность              | Фактическая граница                                                                              |
| ------------------------ | ------------------------------------------------------------------------------------------------ |
| Три AI-режима            | Нет пользовательского переключателя и нового набора допущенных маршрутов                         |
| Bubble                   | Только честно недоступная партнёрская карточка; внешний API не подключён                         |
| «Мой план»               | У нового пользователя пока объясняющая заглушка, не сохраняемый план из разговора                |
| Личная память            | Подтверждённые факты из беседы ещё не записываются как профиль                                   |
| Публичная база знаний    | Есть контракты и offline planner; нет production research/retrieval/publishing                   |
| Полная история на экране | Все сообщения остаются в БД; загрузка старше последних 100 ещё нужна                             |
| Expo                     | Прежний разговорный клиент; нет паритета нового каталога, списка, избранного и встроенной оплаты |
| Телефон/подарок          | Подтверждение телефона и выдача подарка этим изменением не включаются                            |

## Проверки и точки входа

Локальная приёмка рабочего изменения (Node 24.11.1 / pnpm 10.15.0):

- `pnpm check`: **1425 pass**. В том числе contracts 148, API 469, DB 364,
  API client 68 и Web unit 34. Использован одноразовый PostgreSQL 17, а не
  рабочая БД; конкурентное создание и существующие runtime-права проверены
  настоящими независимыми соединениями, без skip.
- Единственный Windows skip — Linux launcher signal test; он отдельно выполнен
  в одноразовом Linux Docker без сети: **1/1 pass**. Пропуск не скрывается.
- Playwright: **172/172**, desktop и mobile-web, без пропусков. Новые 14
  проверок входят в это число: раздельные истории/черновики, reload, закрытый
  разговор, избранное, ошибки чтения, чужой owner и поздний поток после смены
  аккаунта. Скриншоты каталога/списка просмотрены на обоих размерах.
- Export Android/iOS, проверка утечек env, scoped Prettier и `git diff --check`
  прошли. Экспорт не означает готовые нативные экраны каталога.

Сравнение public-таблиц и старых миграционных квитанций при 24 → 25, а также
синтетические rewind/replay 12/18 → 25 сохраняют денежные данные и проверяют
откат при поздней ошибке ACL. Финансовый HTTP-тест отдельно доказывает:
открытие/чтение не вызывают AI, незавершённый запрос блокирует другой диалог
того же владельца, каждый контекст заканчивается своим новым вопросом,
списание остаётся точным ×10.

Локальные результаты не подменяют GitHub CI. Container smoke и допуск будущего
серверного выпуска фиксируются отдельно для закреплённого коммита.
Реальные модели, платежи, рабочая БД и сервер в этой приёмке не вызываются.
