# CG-004 — устойчивый общий API/SSE-клиент

Реализация 22 сентября 2026 в `citygo-platform-review`, отдельная ветка
`codex/api-sse-hardening-cg004` от `1fef2db4` (main после PR #30).
Предыдущий инкремент: [CG-003](cg-003-session-isolation.md).

## Что изменено

- Общие runtime-схемы проверяют все JSON-ответы используемых методов клиента:
  вход, выход, профиль/план/историю, согласие, старт/завершение квеста и Admin.
  Вложенные поля проверяются без приведения неверных типов; неизвестные
  добавочные поля допускаются, но не передаются потребителю.
- Сохранённый профиль с прошедшей датой переезда остаётся читаемым; требование
  будущей даты сохраняется для новой анкеты. Старые необязательные поля бюджетов
  и PostgreSQL-формат времени аудита поддержаны. Идентификаторы остаются opaque
  строками, включая текущие десятичные ID сервера.
- Старые неизменяемые записи журнала бюджета до миграции 0007 могут не содержать
  `userDailyLimitMicros`. Отсутствие допускается только в исторических `from/to`,
  не подменяется нулём/null и не ослабляет схему действующих настроек.
- JSON и SSE читаются с ограничениями времени и объёма. HTML вместо JSON/SSE,
  неверный Content-Type, повреждённый JSON/UTF-8 и несовместимые схемы дают
  понятную ошибку без сырого тела ответа или деталей JSON-парсера.
- Конечный POST SSE-поток поддерживает CR/LF/CRLF, UTF-8 между chunks, начальный
  BOM, несколько `data:`-строк и heartbeat-комментарии. События проходят схему
  до callback. Только валидный `done` с непустым `messageId` подтверждает
  завершение; он освобождает reader немедленно, даже если сервер не закрыл поток.
  EOF без `done`, незавершённый frame и неизвестное/неверное событие — ошибка.
- Abort распространяется на ожидание заголовков и чтение тела. Поздние ответы
  освобождаются; зависший transport или promise отмены reader не удерживает UI.
  Сессионная изоляция CG-003 и обработка защищённого 401 сохранены.
- В Expo явно используется `expo/fetch` с потоковым чтением; новых зависимостей
  нет. API-клиент допускает внедрение транспорта для native и тестов.

## Границы ожидания и памяти

| Ограничение                                         | По умолчанию |
| --------------------------------------------------- | ------------ |
| JSON: заголовки + тело                              | 30 секунд    |
| SSE: весь запрос                                    | 300 секунд   |
| SSE: отсутствие байтов, включая ожидание заголовков | 45 секунд    |
| JSON / суммарный SSE                                | по 8 MiB     |
| SSE frame, включая комментарии и метаданные         | 256 KiB      |
| Число SSE-событий                                   | 100 000      |
| Тело HTTP-ошибки                                    | до 16 KiB    |

Heartbeat сбрасывает только idle-таймер, но не общий deadline. Пять минут
оставляют запас для текущего серверного таймаута RouterAI до 240 секунд;
сервер передаёт heartbeat каждые 15 секунд. Опция `limits` позволяет только
уменьшать положительные целочисленные пределы, не отключать или расширять их.
Пределы применяются к фактически прочитанным байтам, а не `Content-Length`.
Слишком большой ответ отклоняется явно, без тихого обрезания истории.

**Автоматических retry/reconnect нет**, в том числе для GET. POST-команды и чат
никогда не повторяются из-за ошибки/таймаута. Отмена клиента не доказывает,
что сервер не принял действие: перед ручным повтором нужно проверить состояние.

## Проверки

Используются вымышленные данные и тестовый провайдер, без живых LLM-запросов.

- Контракты: тесты вложенных ответов, совместимости старых полей и дат.
- API-клиент: malformed JSON/SSE, split UTF-8/CRLF, фальшивый `done`, ограничения
  строк/frames/events/байтов, stalled fetch/body, idle/общий deadline, abort,
  late response, не завершающийся cancel и отсутствие повторной отправки.
- API integration: схемы принимают ответы настоящего тестового приложения
  на всём пути от регистрации до чата, Admin и `+60 XP`.
- E2E: исходный жилищный маршрут и сессионная изоляция; дополнительно 16 проверок
  сбоев на desktop/mobile-web: malformed dashboard/completion, HTML вместо SSE,
  ложный `done`, oversized frame и зависание до заголовков. Проверяются снятие
  busy, сохранение черновика, отсутствие лишнего запроса и ложного успеха;
  Admin открывается с журналом до появления персонального лимита.
- Typecheck/lint, production Web build и Expo export Android/iOS.

Локальный результат: **lint, typecheck и все unit/integration tests — PASS**,
в том числе контракты 9/9, api-client 28/28, API 80/80. Исходный браузерный прогон
**70/70 PASS**; полный build, startup 3/3 и Expo export Android/iOS — PASS.
Для исправления замечания о старом журнале добавлены один контрактный тест
и два браузерных (desktop/mobile-web). Ошибка воспроизведена тестом до исправления;
после него response-схемы 4/4, все Admin E2E 14/14, typecheck/lint затронутых
пакетов и Web build — PASS. Итог полного повторного CI фиксируется в PR.
Результаты CI фиксируются в PR перед merge. CI проверяет работу
с PostgreSQL в отдельной тестовой БД; локально — изолированный in-memory PGlite.

## Ограничения и следующий шаг

- Экспорт Expo не заменяет проверку на физических Android/iOS. На устройствах
  и в Safari/WebKit ещё нужно проверить streaming, airplane mode, stop/logout,
  просроченную сессию и восстановление после background. Таймеры JavaScript
  могут задерживаться при приостановленном приложении/вкладке.
- Лимиты ограничивают накопление данных клиентом, но не внутренний буфер
  сетевой реализации. Уже принятые сервером действия отмена не откатывает.
- Это проверка текущего wire-контракта, не новое версионирование API и не
  изменение семантики завершения квеста (CG-008). Серверные маршруты, миграции,
  бюджеты, ключи, базы владельца и конфигурация провайдеров не изменены.
- Следующий инкремент после merge — **CG-005**: Expo XP из `result.awarded`,
  последний квест и отдельные busy-состояния. Per-service env остаётся CG-006.

Основа совместимости: [WHATWG SSE parsing](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream)
и [Expo Fetch API](https://docs.expo.dev/versions/latest/sdk/expo/#expofetch-api).
Клиент CityGo намеренно не реализует автоматическое переподключение EventSource:
его протокол — один конечный POST с явным терминальным событием.
