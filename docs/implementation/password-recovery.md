# Восстановление забытого пароля

Подготовлено 24 октября 2026 в отдельной ветке `codex/email-password-recovery`.
Это изменение исходного кода; сервер этим PR не обновляется. Следующий
нереализованный этап выбран из разговорного
[Figma-прототипа](https://www.figma.com/design/6pAycf8MPlTyddwYPH6NEL?node-id=6-10):
Web — `6:10`, мобильный экран — `6:93`.

## Путь пользователя

1. На экране входа выбрать «Не помню пароль» и указать email.
2. Если этот адрес ранее подтверждён и аккаунт активен, получить письмо
   Postbox с шестизначным кодом восстановления.
3. Ввести код, новый пароль и его повтор. Пароль — от 6 до 128 любых символов,
   по тем же правилам, что при регистрации.
4. После успеха войти обычным способом с новым паролем. Все прежние сессии
   этого аккаунта отозваны; автоматического входа после сброса нет.

Форма одинаково отвечает для известного, неизвестного, неподтверждённого
и заблокированного адреса. Она не подтверждает существование аккаунта или
доставку письма. Если отправка недоступна, показывается возможность вернуться
позже; обхода через регистрационный код нет. Для старого аккаунта без записи
`account_email_verifications` автоматическое восстановление недоступно.
Bootstrap `admin@citygo.invalid` также не получает такую возможность.

## Код и ограничения

Код действует 10 минут и используется один раз. Не более пяти неверных
попыток на одну процедуру; ручная повторная отправка не продлевает срок
и не сбрасывает попытки. Новый код заменяет предыдущий. Повторную отправку
можно запросить через 60 секунд; автоматических повторов нет.

Регистрация и восстановление делят существующий журнал ограничений отправки:
до трёх запросов на адрес в час и десяти с IP в час, плюс настроенные общие
квоты. Общие квоты `null` по-прежнему означают отсутствие общего лимита;
эта функция не меняет согласованный почтовый тариф.

Сервер хранит только хеши кода и доказательства процедуры, привязанные к её
назначению, и отпечаток текущего хеша пароля. Обычная смена пароля делает
старый код неприменимым. Успешный сброс атомарно меняет пароль, отзывает
сессии, закрывает другие процедуры этого аккаунта и записывает аудит.
Неподтверждённые запросы не меняют аккаунт и не блокируют существующий вход.

Отправка выполняется после записи процедуры без ожидания почтового
провайдера в HTTP-ответе. Ошибка отправки закрывает только соответствующий
код; поздний результат не меняет более новый код. Общий срок — 25 секунд,
запрос к Postbox — 15 секунд. Завершение API отменяет и дожидается своих
отправок до закрытия соединения с БД. Без подтверждения приёма письма
провайдером код не допускает сброс пароля.

В Web и Expo код, доказательство процедуры и новые пароли находятся только
в памяти экрана. Они очищаются при уходе, истечении срока и завершении.
Запоздалый ответ не меняет состояние другого вошедшего пользователя.
Ответ сброса не перезаписывает cookie: прежняя сессия уже недействительна
на сервере, а параллельный новый вход должен сохраниться.
Секретные поля исключены из журналов. В URL и постоянное хранилище они
не записываются.

## Контракт и подключение

| Маршрут                                   | Назначение                                                  |
| ----------------------------------------- | ----------------------------------------------------------- |
| `GET /v1/auth/password-recovery-policy`   | Доступность восстановления                                  |
| `POST /v1/auth/password-recovery/request` | Email → идентификатор, proof, срок и время до повтора       |
| `POST /v1/auth/password-recovery/resend`  | Ручная замена кода по идентификатору и proof                |
| `POST /v1/auth/password-recovery/confirm` | Код, proof и новый пароль → подтверждение сброса без сессии |

Используются существующие `EMAIL_REGISTRATION_MODE=required`, секрет
регистрации с отдельными назначениями HMAC и ограниченный отправитель
Postbox. Новый ключ, провайдер или платное подключение не нужны. Шаблон
восстановления отделён от регистрационного письма. Схема 28 добавляет только
`password_recovery_challenges`, индексы и защиту неизменяемых полей;
существующие аккаунты не объявляются подтверждёнными.

При будущем выпуске нужны обычные свежая резервная копия, проверки
восстановления, миграция 27 → 28 с минимальными правами и контрольный
сценарий на почте владельца. Этот PR сам по себе не разрешает отправить
контрольное письмо или обновить сервер.

Резерв 5 ₽ CityGo, фактическая стоимость ×10, оплаченные лоты, возвраты и
ЮKassa с чеками не меняются. Автодеплой, ProstoSMS и подарок остаются выключены.

## Проверки

Изолированные тесты проверяют неизвестные адреса и ошибки доставки,
одноразовость, истечение срока, перебор и повторы, отзыв cookie/bearer-сессий,
гонки на PostgreSQL, минимальные права и сохранение данных при 27 → 28.
Web E2E использует вымышленные ответы API; настоящих писем, платежей и
модельных запросов в этих тестах нет. Общий Linux CI и Container smoke
проверяют также существующие финансовые и выпускные ограничения.

Основание защитных решений —
[OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html).
