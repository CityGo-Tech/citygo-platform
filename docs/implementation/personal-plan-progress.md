# Прогресс личного плана и точный источник шага

Задача **CG-042**, отдельный инкремент полного Web-кабинета.

Разработка 28 октября 2026 от `main ebaab219`, обновление ветки 29 октября
относительно `main df4fbe1` после PR #134; схема **36**. Следующий
срез [разговорного прототипа Figma](https://www.figma.com/design/6pAycf8MPlTyddwYPH6NEL?node-id=6-24)
развивает «Мой план» (`6:24`, мобильный образец `6:105`) и обзор действий
пользователя (`6:42`).
Используются существующие карточки, Manrope, цвета и адаптивная рабочая область;
фильтры и счётчики приспособлены к настоящим личным шагам вместо примерных квестов.
Этот PR не обновляет сервер и не включает автодеплой.

## Пользовательский сценарий

В «Мой план» виден общий результат: сколько собственных шагов выполнено из
всех сохранённых. Фильтры «Все», «В работе», «Выполнено» показывают соответствующие
шаги и общее количество каждого состояния. Это количество во всём плане,
а не только в первой загруженной странице из 20 записей.

Пользователь может отметить выполнение, вернуть шаг в работу или удалить
его. После подтверждённого изменения список и счётчики обновляются с сохранением
выбранного фильтра. Если в выбранном состоянии нет шагов, можно вернуться
ко всем; настоящий пустой план по-прежнему предлагает начать разговор.
При неизвестном результате изменения нужно обновить план перед повтором.

«Открыть исходное сообщение» показывает именно то сообщение, из которого
сохранён шаг, вместе с предшествующей историей. Сообщение выделяется и получает
фокус. Оно доступно и за пределами последних страниц переписки, в том числе
в закрытом диалоге. Из просмотра можно вернуться к плану или открыть сам диалог.
Добавлять исходник в избранное для этого не нужно.

Состояние шага меняет только пользователь. Эта функция не начисляет XP,
не завершает жилищный квест, не извлекает факты автоматически и не отправляет
личный план в модель. Память разговора, Bubble и нативный экран Expo остаются
отдельными этапами; существующий PR с памятью не дублируется.

## Совместимость и доступ

- Существующий `GET /v1/personal-plan` сохраняет формат ответа. Необязательный
  `status=pending|completed` фильтрует собственные записи **до** keyset-пагинации.
  Старый вызов `client.personalPlan(before)` продолжает работать для Web и Expo.
- Новый `GET /v1/personal-plan/summary` возвращает
  `{ userId, total, pending, completed }`. Сумма состояний равна общему количеству;
  удалённые записи и чужие источники не учитываются.
- Источник использует существующий маршрут
  `GET /v1/conversations/:id/messages/:messageId/context`, с проверкой владельца
  диалога. Доступ администратора не обходит проверку собственного плана.
- ID остаются строками bigint. Новых таблиц, миграций, прав БД и провайдеров нет.
- Смена фильтра или аккаунта отменяет старую загрузку; её запоздавший ответ
  не подменяет выбранный список. Недоступность источника даёт ошибку и ручной
  повтор без отправки сообщения помощнику.

## Проверка и выпуск

Приёмка включает фильтрацию и счётчики за пределами 20 записей, скрытые и
удалённые источники, чужого владельца, строгую проверку ответов, bigint-курсоры,
запоздавшие ответы и смену сессии. Браузерный сценарий проверяется на широком
и узком экране, с клавиатурой и ошибками загрузки. Полный локальный прогон
фиксируется по точному коммиту отдельно от статусов GitHub и серверной приёмки.

Сохраняются три режима ИИ, резерв **5 ₽ CityGo**, фактический тариф RouterAI
**×10**, фиксированные **3 ₽** за успешный ответ «Минимума», действующий магазин
ЮKassa с чеками, подтверждение телефона и разовый подарок **500 ₽**.
Разработка и тесты не выполняют настоящих AI-запросов, платежей, писем или SMS.
Автодеплой остаётся выключенным; отдельный PR не является выпуском.
