# Поиск сообщений внутри диалога

В открытом или завершённом диалоге кнопка «Найти в диалоге» открывает отдельное окно. Поиск находит сообщения пользователя и помощника по буквальному фрагменту текста без учёта регистра. Проценты, подчёркивания и обратная косая черта не становятся шаблонами. Нажатие «Открыть сообщение» показывает точное найденное сообщение и предшествующую историю через существующий reader контекста. Закрытие окна возвращает пользователя к прежнему диалогу и неотправленному тексту.

## API и границы

`GET /v1/conversations/:id/messages/search?search=...&before=...` требует действующую сессию и проверяет активного владельца выбранного диалога. Роль администратора не даёт доступа к чужому диалогу через этот endpoint. В транзакции используется существующий порядок коротких блокировок: пользователь, затем диалог. Завершённые диалоги доступны для чтения.

Запрос содержит обязательную строку `search` длиной 1–160 символов после обрезки краевых пробелов и необязательный канонический положительный int64 `before`. Другие параметры, NUL, непарные суррогаты и некорректные ID отклоняются. ID сохраняются строками; сравнение в клиенте использует BigInt. Курсор должен указывать на совпадающее видимое сообщение того же диалога и запроса.

Ответ содержит `userId`, `threadId`, `search`, до 20 совпадений с ID, автором, помощником, статусом и фрагментом до 512 UTF-16 единиц. Совпадения упорядочены по ID от новых к старым. 21-е совпадение используется только для определения `nextCursor`. Все последующие страницы читаются по `id < before`, без OFFSET. Браузер удерживает не более 200 видимых совпадений и продолжает чтение ранних страниц; об ограничении видимого списка сообщает текст.

Поиск параметризован через PostgreSQL `position(lower(search) in lower(content))`, без LIKE и регулярных выражений. Используются существующие индексы и ограничение одним диалогом. Поиск подстроки может просматривать много сообщений внутри большого диалога; постоянное время выполнения не обещается. Новые индексы и миграции не добавлены.

## Приватность и отмена

Ответы имеют `Cache-Control: no-store`. Общий HTTP-логгер сохраняет только путь без query, поэтому текст и курсор не попадают в журнал запросов. Окно результатов и контекста скрыто от Вебвизора, поле поиска имеет `ym-disable-keys`. Текст поиска не добавляется в адрес страницы, аналитику, localStorage или sessionStorage.

Состояние принадлежит одному пользователю, диалогу и сессии и существует только в оперативной памяти. Новая строка поиска отменяет предыдущий запрос. Закрытие окна, смена аккаунта/диалога или прекращение сессии уничтожает результаты; поздний ответ не восстанавливает их, даже если транспорт проигнорировал отмену. Ответы с чужим владельцем или диалогом отклоняются. Ошибки не отображают внутренние данные сервера.

Поиск и просмотр контекста не отправляют сообщений, не вызывают моделей, не изменяют избранное/план, расходы, резерв, баланс, оплату, телефон или подарок. Конфигурация провайдеров, тарифы и автодеплой не меняются.

## Проверки

Синтетические проверки покрывают контракт и клиента, владельца и отозванную сессию через HTTP, буквальный Unicode-поиск и int64-курсор, неизменность всех таблиц и последовательностей, отмену и поздние ответы, окно 200 совпадений. Отдельный PostgreSQL-тест с временной БД и существующими runtime grants проверяет повторное чтение статуса владельца после ожидания блокировки; запускается только с явно заданным disposable `TEST_DATABASE_URL`.

`e2e/conversation-message-search.spec.ts` проверяет поиск свежих и ранних сообщений, переход к точному контексту, возврат к результатам и черновику, ошибки/пустую выдачу, закрытие до ответа и смену аккаунта во время запроса. Все HTTP-запросы браузерных сценариев подменяются синтетическими ответами, реальные ИИ/платежи/почта/SMS не вызываются.
