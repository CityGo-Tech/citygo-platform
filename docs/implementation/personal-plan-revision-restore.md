# Восстановление сохранённой версии шага

Функциональное продолжение Figma 6:25 (предыдущая/новая версия), на существующих компонентах и токенах. Новых изображений нет.

Пользователь сравнивает фактически сохранённую версию с текущей и отдельно подтверждает восстановление. Восстанавливаются название, описание, статус и весь чек-лист. Сервер получает только номера выбранной и ожидаемой текущей ревизий; содержимое берёт из неизменяемой истории своего живого шага. Восстановление создаёт новую ревизию и новую запись истории, не переписывает старые данные, источник или дату создания. Удалённый шаг не восстанавливается.

Транзакция блокирует пользователя, затем шаг, проверяет active/password gate, принадлежность источника и CAS. Две конкурентные попытки дают одного победителя; повтор завершённой команды конфликтует без нового изменения. Ошибка записи чек-листа/истории откатывает всю операцию. Максимальная ревизия и неизвестный/чужой снимок отклоняются. Новые миграции и SQL-права не требуются; применённые миграции и существующие ограниченные grants сохраняются.

POST /v1/personal-plan/:id/history/restore использует обычную аутентификацию, origin/contract guards, write rate limit и no-store. Новых AI, финансовых, XP, платёжных, телефонных или провайдерских операций нет. Ошибка/потеря ответа не вызывает автоматический повтор: интерфейс предлагает обновить историю. Отмена до подтверждения не пишет ничего; смена сессии скрывает частные данные и игнорирует поздний результат. Подтверждение и история замаскированы от Метрики; текст не записывается в URL или отдельное локальное хранилище.

Проверки: contracts/client/state, PGlite atomic rollback/private ownership, HTTP authentication/CAS/protected-state, существующий PostgreSQL runtime-grants/race drill, desktop/mobile confirmation/cancel/reload/conflict. Полный совместный Linux/Docker-прогон выполняется отдельно root для пакета фичей. Слияние, публикация и обновление сервера этим PR не выполняются.
