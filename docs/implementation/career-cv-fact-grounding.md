# Основания фактов в карьерном черновике

Триггер дефекта: пользователь сообщает свой опыт рядом с требованиями вакансии.
Помощник может перенести требование «объяснять выводы бизнесу» в прошлый опыт
кандидата. Точный фрагмент из одного сообщения не доказывает, что это личный факт.
В закреплённом диалоге Job Search Mentor запрос о резюме также остаётся у этого
помощника, поэтому одного изменения инструкции Resume Builder Expert недостаточно.

## Поведение

В `/v1/threads/:id/messages` запросы о CV/резюме/сопроводительном письме к обоим
карьерным помощникам используют отдельный реестр личных фактов. Поддерживаются
явные заголовки «Подтверждённые факты:», «Факты профиля:», «Мой опыт:», «Мои навыки:»,
а также Confirmed personal facts / My experience / My skills. Блок должен быть
перед вакансией. Новый такой блок заменяет старый; это позволяет отозвать навык.
Неразмеченная коррекция/отзыв или смена кандидата также очищает прежний реестр и
просит актуальный полный блок. Запрос добавить опыт вне блока сам по себе фактом
не является. Первое уточнение показывает короткий пример разделения опыта и вакансии.
Реестр строится по сохранённым пользовательским репликам owner-scoped admission
(последние 100 сообщений этого диалога), даже если ответ на новую редакцию был
прерван. Отфильтрованный контекст генеративной беседы не является реестром фактов:
он может исключать неуспешные раунды. Ни один ответ помощника источником фактов
не становится, и interrupted assistant текст не возвращается в контекст модели.
Требования вакансии, прошлые ответы помощника, отрицания, инструкции и следующий
заголовок документа не становятся личными квалификациями. Неразмеченное или
неоднозначное описание вызывает одно безопасное уточнение без model-call.

Пример:

```
Адаптируй резюме.
Подтверждённые факты: 2 года с SQL и Excel; регулярные отчёты.
Требования вакансии: Power BI; объяснять выводы бизнесу.
```

Один запрос модели выбирает релевантные ID и точные цитаты из реестра, порядок и
разделы, коды редакторских рекомендаций и одного уточнения. Сервер проверяет JSON
и ссылки на факты. Готовый черновик содержит только эти исходные цитаты, а советы
и вопрос отделены от сведений о прошлом опыте. Дополнительного вызова модели
для проверки нет. Обычная подготовка к собеседованию/стратегия поиска сохраняет
генеративный поток.

План модели хранится в приватном буфере до завершения и проверки. Сырые чанки не
выдаются по SSE и не записываются в историю даже при обрыве провайдера. Неверный
план даёт уточнение и `VALIDATION_ERROR`, не событие `done`. Нормальные ограничения
длины, согласия, квоты, запрет retry после первого токена и денежный учёт действуют.

## Плата и совместимость

Схема БД, API-контракт и провайдеры не меняются. При отсутствии реестра нет
попытки провайдера/денежного резерва. Успешный фиксированный Minimum использует
существующий тариф 3 ₽. Для неуспешного Minimum фиксированная плата не списывается;
защитная аренда мощности провайдера может оставаться до своего срока. RouterAI
уже мог понести реальную стоимость даже при отклонённом ответе: она требует
существующей сверки квитанции/резерва, и не объявляется нулевой.

## Границы

Это проверка точного происхождения и структуры, не универсальная семантическая
проверка правды. Пользовательский блок является самоотчётом, не внешней проверкой
трудового стажа. Свободная перефразировка фактов в этом узком контуре ограничена
отбором/структурой, чтобы не добавить новый смысл. Вложенный художественный текст
или ложный самоотчёт не становятся достоверными от наличия заголовка. Пользователь
проверяет сведения перед отправкой работодателю; CityGo ничего ему не отправляет.
Нераспознанные формулировки намерения и другие помощники не покрыты полной
семантической гарантией. Расширение формата требует новых контрпримеров.

## Регрессии

- `career-grounding.test.ts`: происхождение, Power BI/бизнес только в вакансии,
  отрицания до разбивки перечисления, чужой образец, предыдущая галлюцинация,
  корректировка фактов, неизвестные ID/изменённые цитаты/свободный вывод.
- `career-grounding.integration.test.ts`: реальный Fastify HTTP, SSE, PGlite,
  сохранение и чтение истории, оба закреплённых помощника, один вызов, отсутствие
  утечки первого вредного чанка и при обрыве. Провайдер заменён синтетическим double.
  Трёхходовый HTTP regression проверяет отзыв SQL/новый Excel после invalid и
  interrupted ответа: следующий запрос получает только актуальный Excel.
- `ai-modes.integration.test.ts`: локальное уточнение без платы, ровно 3 ₽ только
  за валидный Minimum, возврат резерва для отклонения/обрыва, сохранение защитной
  аренды мощности. Здесь деньги и провайдер полностью синтетические.

Локальный PASS подтверждает эти тестовые контуры. Он не является live-приёмкой,
исследованием на пользователях или доказательством выпуска на pilot.
