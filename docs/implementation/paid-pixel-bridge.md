# CG-ADS-002 · Управляемое подключение VK и Avito

Подготовлено поверх CG-ADS-001 / PR #188. Код не включает рекламу, сбор на
рабочем сервере или автодеплой. Новых миграций и регистрационных галочек нет.

## Публичные настройки

| Система          | ID          | Событие подтверждённой регистрации |
| ---------------- | ----------- | ---------------------------------- |
| Яндекс.Метрика   | `113847047` | `citygo_registration_completed`    |
| VK / Top.Mail.Ru | `3812681`   | `citygoRegistrationCompleted`      |
| Avito            | `3496456`   | `citygo_registration_completed`    |

Avito `3496456` — исправленный владельцем счётчик правильного аккаунта.
Прежний счётчик в этой реализации не используется. Создание целей и получение
данных в рекламных кабинетах этим PR не подтверждаются. В Метрике по проверке
владельца подготовки уже настроены 30 целей, включая
`citygo_landing_cta_clicked`; регистрация выбрана приоритетной.

По умолчанию все рекламные SDK выключены. Для будущей отдельно разрешённой
сборки к существующим настройкам Метрики добавляются только публичные входы:

```dotenv
NEXT_PUBLIC_CITYGO_AD_PIXELS_ENABLED=enabled
NEXT_PUBLIC_CITYGO_VK_PIXEL_ID=3812681
NEXT_PUBLIC_CITYGO_AVITO_COUNTER_ID=3496456
```

Это build-time параметры Next. Изменение окружения уже собранного образа их
не включает. В `.env.web.example` и Dockerfile переключатель остаётся
`disabled`, ID пустые. `scripts/env.mjs` и Turbo допускают ровно эти имена
только в Web/build; API, worker, migrator, mobile и обычный test их не получают.
Тестовые ожидания `CITYGO_*_E2E_*` разрешены отдельно только в test scope и
сами сбор аналитики не включают.

Рекламные счётчики используют существующий общий выбор необязательной
аналитики, поэтому требуют включённой конфигурации аналитики Метрики.
Готовность сетевых SDK независима: недоступность Yandex tag.js не мешает
разрешённому рекламному документу. Для авторизованного пользователя при этом
сохраняется прежняя успешная first-party проверка analyticsIdentity; её
401/403 или другая неразрешённая ошибка не обходятся.

Штатный publisher публикует испытанные образы и не должен пересобирать их с
другими флагами. Перед будущим выпуском оператор фиксирует все шесть публичных
входов, включая три прежних параметра Метрики, в проверенной сборке и её
metadata. Ранее сохранённые локальные controllers/permissions не меняются и
не считаются допуском для новых входов. Smoke по умолчанию сохраняет выключенные
Docker defaults; включённый вариант проверяется отдельно сетевыми моками.

## Жизненный цикл и границы данных

SDK работают в отдельном пустом документе `/paid-pixels/frame.html`, а не
в DOM кабинета. Родитель создаёт его только после существующих проверок
сессии, роли, текущего URL, DNT/GPC и отказа от аналитики. При отзыве,
смене сессии/аккаунта, блокировке, pagehide и уходе компонент удаляет iframe.
Обработчики SPA и таймеры SDK принадлежат удалённому документу; удалением
одного script в живом кабинете остановка не имитируется.

`sandbox="allow-scripts allow-same-origin"` нужен обычным cookie и History API
провайдеров. Это граница жизненного цикла и области DOM для одобренного кода,
**не изоляция от намеренно вредоносного same-origin скрипта**. Подключение
предполагает доверие указанным поставщикам SDK. CSP ограничивает загрузку
двумя SDK и их основными коллекторами; необязательный VK cookie-sync loader
не разрешён. Основные цели проверены с действительным кодом SDK и этой CSP.

Шаблон host nginx сохраняет `DENY` для продукта и админки, разрешая
`SAMEORIGIN` только успешному ответу 200 точного пути `/paid-pixels/frame.html`.
Ошибки на этом пути также сохраняют `DENY`. На двух рекламных
статических ресурсах действует `no-referrer`. Upstream framing/referrer
заголовки скрываются, чтобы не получить одновременно `DENY` и `SAMEORIGIN`.
Отдельного location и обхода maintenance gate нет: закрытый ingress по-прежнему
возвращает 503 с `DENY`. Будущий разрешённый выпуск должен применить и
проверить этот nginx template; одной замены Web-образа недостаточно.

`postMessage` требует точного source, origin, версии, случайного канала и
набора полей. Допускаются только публичные ID, канонический адрес `/` или
`/landing/v1|v8` и четыре UTM по существующему контракту. До загрузки SDK
History API меняет только URL пустого child document на этот адрес.
Referrer пуст. Не передаются user ID, email, телефон, содержимое аккаунта,
вопросы, ответы, OTP, auth-токены, произвольный query или click ID.

Числовые и содержащие точку публичные campaign-slug поддерживаются наравне
с существующей атрибуцией. Синтаксическая проверка не распознаёт персональные
данные: в кампании оператор использует только заранее заданные публичные метки.

Цель регистрации поступает исключительно из существующей квитанции успешного
подтверждения email для того же обычного пользователя и session signal.
Submit формы, отправка кода, вход и подарок её не заменяют. Memory-only флаг
квитанции и однократная команда child document исключают повторную отправку
на уровне приложения. Сменивший аккаунт, отменённый или истёкший поток не
восстанавливается. Содержимое кабинета не используется для рекламных событий.

Нет невидимого `noscript`-fallback, верхнеуровневых `_tmr`/`_apxl`, перезагрузки
формы входа, платных проб и автоматических повторов при блокировке SDK.
Успех локальной очереди не является гарантией внешней доставки: браузер,
сеть или поставщик могут потерять событие; сам SDK может использовать
резервный транспорт. Внутренняя атрибуция созданного аккаунта остаётся в БД.

## Проверка и запуск

Целевые проверки включают конфигурацию и отрицательные URL/payload, privacy и
401/403, действительный hook с квитанцией регистрации при ещё не загруженной
Метрике, обычные цели без auth receipt, admin/DNT/GPC/отказ, поздний SDK,
удаление iframe и регистрацию на узком/широком экране. Внешние запросы в
бразуерных тестах полностью подменяются. Отдельная локальная проба с текущими
байтами настоящих Avito/VK SDK проверяет по одной цели, публичный URL,
пустой referrer, отсутствие приватных данных и прекращение запросов после
удаления документа. Реальных событий в кабинеты она не отправляет.

После разрешённых merge и выпуска нужны отдельный чистый визит по каждой
рекламной ссылке, одна контрольная подтверждённая регистрация и проверка
получения точных целей в обоих кабинетах. До этого не считать оптимизацию
по конверсиям готовой и не запускать рекламу. Тарифы, постоплата, ЮKassa с
чеками, подтверждение телефона, подарок и три режима ИИ не изменяются.

Основные первоисточники: [Avito SDK](https://ac.avito.ru/tag.js),
[официальная установка Avito](https://ads-help.avito.com/external/pixel-avito-ads),
[события Avito](https://ads-help.avito.com/analytics/counter-events),
[VK / Top.Mail.Ru JavaScript API](https://top.mail.ru/help/ru/api/jsapi).
