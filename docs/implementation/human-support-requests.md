# Обращения к человеку

Отдельный Web/API-срез от main `13d238b`, схема 37. Основа интерфейса —
[Figma 6:72](https://www.figma.com/design/6pAycf8MPlTyddwYPH6NEL?node-id=6-72)
и [6:73](https://www.figma.com/design/6pAycf8MPlTyddwYPH6NEL?node-id=6-73):
Manrope, центральная карточка с отступом 24 px, радиусом 24 px, заголовком
32 px и существующими компонентами/оригинальными портретами оболочки.

«Помощь человека» доступна в профиле и боковой панели. Пользователь сам вводит
вопрос от 20 до 4000 символов и нажимает отправку. Сохраняется только этот текст,
без истории диалога, вызова модели, обязательной анкеты или проверки баланса.
Длина считается по Unicode-кодовым точкам одинаково в форме, API и PostgreSQL;
счётчик учитывает emoji как один символ. NUL и непарные суррогаты отклоняются
до записи. Явный отказ проверки возвращает возможность исправить вопрос.
Квитанция показывает действительные номер и время сохранения. Статусы —
«Открыто» и «Закрыто владельцем»; отправка уведомления, принятие в работу,
ответ специалиста и круглосуточная помощь не обещаются. Экстренные вопросы
этим каналом не обслуживаются. Вопросы и контакты маскируются для аналитики.

## API и хранение

- `POST /v1/support-requests`: `{ operationId, body }`, владелец из текущей сессии.
- `GET /v1/support-requests`: собственные обращения, `before` и `status` до
  keyset-пагинации по строковым bigint, по 20 записей.
- `GET /v1/admin/support-requests` и `/:id`: действующая роль admin/super admin,
  актуальная сессия, только реальные ID/email/логин владельца и сохранённый текст.
- `PATCH /v1/admin/support-requests/:id`: явный статус и `expectedRevision`.
  Конфликт версий не перезаписывается. Закрытие не отправляет письмо или SMS.

Миграция `0037_human_support_requests.sql` добавляет одну таблицу и индексы.
Владелец, текст, UUID операции, хеш и дата создания неизменяемы. Повтор UUID с
тем же нормализованным текстом возвращает прежнюю квитанцию, с другим — 409.
Сохранение и технический аудит атомарны. Неизвестный результат в Web сохраняет
тот же UUID/текст для явного повтора; автоматических повторов нет. Лимит —
200 сохранённых обращений на аккаунт; частота HTTP ограничена отдельно.

Каждая операция повторно проверяет активный аккаунт, пароль, срок текущей
сессии и последнее действительное согласие на обработку персональных данных.
Admin-права перечитываются под общим security lock в транзакции. В аудит
попадают ID/статус/версия/число строк, без текста вопроса, email или секретов.
Ответы `no-store`; данные не сохраняются в browser storage. Выход/смена сессии
отменяет запросы, чужой или поздний ответ не показывается. Админка дополнительно
очищает открытые обращения при скрытии вкладки или повторном фокусе.

API имеет SELECT/INSERT и UPDATE только состояния/версии/дат. Worker не получает
прав. Существующие инструменты обслуживания отказывают при истории обращений
с `HUMAN_SUPPORT_HISTORY_REQUIRES_REVIEW`, не распространяя старое разрешение
очистки на новые данные.

Проверки: строгие контракты, точный replay, чужой владелец, текущая роль/сессия,
CAS, bigint-пагинация, отсутствие AI/денежных записей, безопасный аудит,
поздние ответы и неизвестный результат, минимальные PostgreSQL-права и гонки,
Web-сценарий сохранение → просмотр admin → закрытие → обновление владельца.
PostgreSQL-тест требует явно заданную одноразовую локальную БД; иначе пропускается.
Широкий и узкий браузерные сценарии используют только тестовый API в памяти.

Три режима ИИ, резерв 5 ₽, RouterAI ×10, фиксированные 3 ₽ за успешный «Минимум»,
ЮKassa с чеками, телефон и разовый подарок 500 ₽ сохраняются. Реальные провайдеры,
письма, SMS, платежи, ключи, сервер и автодеплой не затрагиваются.
