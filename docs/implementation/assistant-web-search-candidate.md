# Источники веб-поиска — локальный кандидат

5 ноября 2026. Отдельная ветка от `main 17844bc`, схема **47 без новых миграций**.
Это подготовка следующего этапа качества, а не включённый поиск на сервере.

## Поведение

Для тестового «Максимума» добавлен отдельный адаптер RouterAI Chat Completions:
точная модель `openai/gpt-6.1-sol`, провайдер OpenAI, фильтр `us`, без fallback,
`plugins: [{ id: "web", engine: "native", max_results: 5 }]`.
Кандидат получает отдельную инструкцию `routerai-native-web-search-instructions-v1`:
использовать поиск для меняющихся внешних сведений, предпочитать первичные
источники, различать даты публикации и события, отделять подтверждённые сведения
от вывода. Результаты поиска считаются недоверенными данными. Сам поиск не
означает чтения всего сайта, PDF или изображения. Реальная отправка и офлайн-
предпросмотр используют одинаковый выбор инструкции; версия входит в идентичность
кандидата. Тексты инструкций остальных конфигураций остаются побайтно прежними.

Используется один нестриминговый ответ JSON: публичная документация RouterAI
описывает аннотации именно этого формата, но не устанавливает их wire-формат
в потоке. Автоматического повтора при ошибке нет.

Весь ответ проверяется до публикации текста. Допускается только один завершённый
ответ требуемой модели, непустой текст и 1–256 упоминаний URL. Повторные
канонические URL сворачиваются с сохранением первого названия в список
не более 10 уникальных источников; каждое упоминание проходит проверку. Адаптер ограничивает
JSON одним МиБ, текст — 128 000 единиц UTF-16, метаданные источников — 16 КиБ.
Generation ID сохраняется до проверки последующих полей. Некорректный ответ
завершает попытку как прерванную, без списка источников и без повторного вызова.

Завершённый ответ хранит `generation.webSources` с версией `routerai_native_v1`,
названиями и URL. Подпись «Источники» и обычные кликабельные ссылки доступны в
полном диалоге, истории и полном просмотре исходного сообщения в Web после
финальной загрузки сохранённого состояния. В Expo источники показываются у уже
загруженных сохранённых сообщений; отдельная пагинация и полный просмотр
исходного сообщения в нативном клиенте этим PR не добавляются. Старые ответы без этого поля читаются
как раньше. Markdown модели или пользователя не превращается в метаданные поиска.
Цитаты не добавляются к прерванному ответу, пользовательскому сообщению или
другому провайдеру. Общий байтовый предел страницы истории учитывает метаданные.

Ссылки принимаются только как публичные HTTPS URL без credentials, управляющих
символов и локальных/частных IP или имён. Проверка текстовая: она не делает DNS,
не загружает страницы и не доказывает безопасность будущего перенаправления или
истинность утверждений модели. Видимый домен помогает пользователю проверить
источник. Ссылки имеют `noreferrer`, содержимое скрыто от Метрики.
Диапазоны цитирования не угадываются: единицы индексов RouterAI не подтверждены.
Краткие карточки, TXT-выгрузки и админский интерфейс не заявлены как полный показ
источников. Существующий SSE-протокол не расширен; большие дельты разбиваются на
кадры до лимита старого клиента без разрыва Unicode-пар.

## Допуск и стоимость

`AI_MAXIMUM_WEB_SEARCH=disabled` по умолчанию. Значение
`routerai_native_candidate_v1` допустимо только вне production и при выключенном
списании с клиентов. Ограничение проверяют config, конструкторы режимов и
исполнения, а обработчик завершения повторно проверяет точный маршрут и модель.
В режиме кандидата чтение чека запрещено до сетевого запроса.

При выключенном поиске policy/execution/catalog ID прежних режимов остаются
байт-в-байт прежними. Кандидат имеет отдельные идентификаторы и раскрытие факта
поиска в описании политики. Память v16 разрешена с кандидатом только в узкой
неоплачиваемой test/development-конфигурации: legacy billing, credit disabled,
full reservation setting, operator ceiling, fixed Minimum disabled. Эта ветка
не добавляет production runtime и не ослабляет допуски рабочего v16.

`max_results=5` ограничивает число результатов, **не** число платных поисков и
не расходы. Описание `total_cost` в публичной OpenAPI-схеме недостаточно, чтобы
подтвердить включение всех native search fees, окончательность цены и сверку
позднего чека. Поэтому прежнее правило `has_web_search=false` для оплачиваемых
чеков не изменено, стоимость не оценивается по токенам или прайсу.

Следующий допуск — отдельно разрешённая владельцем одна контрольная попытка с
неперсональным вопросом и согласованной стоимостью, сопоставлением generation ID,
результата, аннотаций и полного чека. Только после доказательства полной цены
можно готовить отдельную проверенную платёжную реализацию и выпуск. Этот PR не
выполняет такую попытку, не заявляет реальное качество поиска и не включает его
пользователям. Текущие «Баланс» и «Минимум», ×10 и 3 ₽, списание после ответа без
удержания, ЮKassa с чеками, телефон и подарок не меняются.

## Проверки

Синтетические тесты проверяют wire-запрос, model/provider pinning, отсутствие
fallback и повторов, bounded JSON/Unicode, обязательные аннотации, блокировку
платёжного чека, неизменность старых ID, сохранение/чтение/пагинацию источников,
изоляцию владельцев, безопасные ссылки и отсутствие источников из Markdown.
E2E проверяют показ после перезагрузки на desktop/mobile. Моки не подтверждают
возможности реального gateway. Финальные результаты Linux CI и Container smoke
прикрепляются к точному коммиту; подготовка не означает слияние или выпуск.
