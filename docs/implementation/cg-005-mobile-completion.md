Ветка `codex/mobile-completion-cg005` от `ddc6646d` (main после PR #31).
Рабочая копия — только `citygo-platform-review`. Предыдущий инкремент:
[CG-004](cg-004-api-sse.md). Дата: 22 сентября 2026.

## Реализация и критерии приёмки

- Сообщение о начислении использует фактический `result.awarded`, а не `60`.
  При повторном завершении с `awarded: 0` показано отсутствие новых XP.
  Общий баланс берётся только из dashboard, без оптимистического прибавления.
  Подписи ожидаемой награды в карточке/кнопке используют `quest.xpReward`.
- Следующий квест показывается только по свежему серверному плану, который
  подтверждает завершение текущего. Используется «Доступный квест», а не
  неподтверждённое обещание нового unlock. Для locked следующего шага явно
  сказано, что он пока недоступен.
- После последнего квеста — честный итог «Все квесты текущего плана завершены».
  Итоговая карточка восстанавливается и после перезапуска из dashboard;
  пустой план не считается завершённым. История чата остаётся доступной.
- Подтверждённая награда хранится в памяти текущей сессии до обновления плана.
  Если completion POST прошёл, а последующий GET не прошёл, receipt не теряется
  и не выдаётся за обновлённый баланс. «Обновить план» повторяет только GET.
  Повторная кнопка завершения этого квеста заблокирована до синхронизации.
- Вместо одного безымянного busy — состояния входа, анкеты, согласия, старта,
  завершения, обновления, выхода и чата. У чата есть streaming/stopping/refreshing.
  «Прервать ответ» доступно только во время streaming, включая ожидание первого
  токена; после stop или окончания потока, во время GET истории, оно недоступно.
- Синхронный gate предотвращает двойное нажатие до перерисовки disabled-кнопки.
  Logout может прервать операцию. Поздние `finally`/refresh старой операции
  не снимают блокировку новой операции/аккаунта. Receipt и pending очищаются
  вместе с прежними пользовательскими данными по правилам CG-003.

Операции остаются взаимно исключающими; разделение состояния не означает
параллельного сохранения и генерации. Автоматических повторов POST нет.
Остановка клиента не откатывает уже принятое сервером действие.

## Ручная проверка на тестовой среде

Только синтетический профиль/тестовый провайдер, без production-данных:

1. Завершить обычный квест: notice соответствует `awarded`, общий XP — ответу
   dashboard, следующий шаг доступен только если это подтвердил сервер.
2. Открыть тот же квест в двух сессиях, завершить в первой, затем во второй:
   вторая показывает 0 новых XP, баланс не удваивается.
3. Завершить последний квест и перезапустить приложение: виден итог плана,
   нет обещания следующего квеста, история доступна.
4. Задержать/отклонить GET после успешного completion: receipt остаётся,
   повторный completion недоступен; «Обновить план» восстанавливает прогресс.
5. Во время анкеты, согласия, completion и ручного refresh нет stop-кнопки.
   Во время чата stop работает до первого токена; при обновлении истории
   после завершения/stop кнопки уже нет. Вход/выход и ошибки освобождают pending.
6. Logout во время completion/чата → вход B: нет receipt/черновика/суммы A;
   поздняя операция A не включает кнопки B до окончания его собственной операции.
