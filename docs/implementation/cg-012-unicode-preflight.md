# Unicode N3 — offline-проверка и варианты решения

**5 октября 2026. Статус: техническая подготовка; N3 не закрыт.**
База — `main` после [PR #81](https://github.com/CityGo-Tech/citygo-platform/pull/81).
Исходный риск описан в [CG-012B](cg-012-draft-recovery.md#ограничения-среды-выполнения-и-допуска-runtime).
Реальный API остаётся запрещён; [CG-012C](cg-012-safe-api.md) не меняется.

## Что именно нужно защитить

v1 сохраняет NFC/trim-нормализованные строки. Reader проверяет исторический
JSON схемой v1 и требует точного равенства, не нормализуя/перезаписывая его.
Смена Unicode-таблиц может изменить NFC строки, содержавшей прежде неназначенный
символ; тогда тот же снимок не пройдёт строгое чтение.

Для символов, назначенных в обеих версиях, действует стабильность нормализации
Unicode 4.1+. Это не означает, что любой ранее неназначенный code point безопасен.
Основание — [UAX #15, раздел 3](https://www.unicode.org/reports/tr15/#Versioning_and_Stability).
Источник TS закреплён, но он не фиксирует Node, ICU или зависимости Zod.
Факт сбоя реальной исторической строки на другой среде **не воспроизведён**.

## Что добавлено сейчас

[housing-unicode-preflight.mjs](../../scripts/housing-unicode-preflight.mjs)
читает только два фиксированных checked-in файла: исходный `housing-v1.ts`
и три синтетических `housing-v1.json` снимка. Не принимает путь к дампу/URL,
не открывает БД, не загружает `.env`, не вызывает модель и не меняет данные.
Для исходника/fixtures использованы **прежние** reviewed SHA-256 pins.

Отчёт содержит только:

- фактические Node/ICU/Unicode и сравнение с локальным baseline
  **24.11.1 / 77.1 / 16.0**;
- совпадение pins, число снимков и неканонических/невалидных снимков v1;
- агрегаты строк, non-NFC, неназначенных code points и одиночных surrogate;
  ключи JSON также проверяются; корректная surrogate pair emoji не считается
  одиночным surrogate;
- `n3Closed:false`, `realApiApproved:false` независимо от положительного результата.

Baseline — наблюдавшаяся среда разработки, **не утверждённый production pin**.
`baseline_match` означает только совпадение среды/трёх fixtures в этом запуске.
`review_required` и exit 1 означают необходимость разбора, не автоматическую
порчу production. Обновлять pins/fixtures ради зелёного отчёта нельзя.
Классификация `Cn/Cs` использует таблицы **фактического** Node; на более новой
среде это не проверка принадлежности Unicode 16. Для такого теста нужна
закреплённая таблица baseline либо запуск на действительно закреплённой среде.

Скрипт загружает исходный валидатор v1 через `tsx`, а не потенциально старый
`dist`; отдельно существующий DB-набор продолжает проверять настоящий reader.
Это не новый полноценный UAX conformance corpus, не проверка всего хранилища,
не DB readiness и не принятие новой политики допустимого пользовательского ввода.

## Как повторить

После frozen install закреплённых зависимостей, в чистом test-окружении:

```sh
pnpm exec node --import tsx --test scripts/housing-unicode-preflight.test.mjs
pnpm exec node --import tsx scripts/housing-unicode-preflight.mjs
```

В подготовленной Windows-копии используется безопасный launcher:

```sh
node .local/handoff/pnpm-safe.mjs exec node --import tsx --test scripts/housing-unicode-preflight.test.mjs
node .local/handoff/pnpm-safe.mjs exec node --import tsx scripts/housing-unicode-preflight.mjs
```

Новая проверка пока запускается отдельно; `pnpm check`/CI/deploy не объявляются
автоматически проверяющими её. Скрипт не выдаёт разрешение перепинить toolchain
или запустить сервер с другим NODE_ENV ради прохождения.

## Предлагаемое техническое решение перед реальной активацией

1. Зафиксировать фактический writer/reader профиль и dependency lock для v1;
   больше не полагаться только на плавающий `node:24-bookworm-slim`.
   В rollout проверять профиль выполняемого контейнера, а не только builder.
2. Для **новых** R1-команд отдельно принять правило поддерживаемого Unicode:
   well-formed строки и отсутствие code points, неназначенных в baseline.
   Проверять до NFC/trim, не заменять символ молча. Не ограничивать ввод одной
   кириллицей и не менять замороженные правила `housing-v1.ts` задним числом.
   Сообщение об отказе/исправлении и применимость ко всем писателям требуют тестов.
3. Перед сменой профиля: полный normalization conformance corpus нужной версии,
   прежние positive/negative v1 fixtures, writer/replay/reader и отдельная
   разрешённая read-only проверка исторических строк на обеих средах.
   Неназначенные старые символы требуют явного решения, не fallback reader.
4. Если в старом v1 они уже есть, оставить совместимый reader до принятой
   versioned migration/новой схемы; не выдать его перезаписанный результат
   за первоначальный. Анализ working DB сейчас не разрешён и не выполнен.

Pin сам по себе не обеспечивает будущую переносимость; фильтр **только новых**
команд не исправляет старые строки; три fixtures не доказывают произвольную
Unicode-совместимость. Нужна комбинация выбранного правила, исторического
разбора и release-проверок. Альтернатива — отдельный устойчивый versioned
normalizer с закреплёнными Unicode-таблицами; это большая реализация и новый
conformance/licensing review, а не замена текущего `.normalize()` в одном месте.

Этот документ предлагает следующий отдельный инкремент и его границы.
Dockerfile, CI, зависимости, API/readiness, reader/writer и fixtures v1
не менялись. До исполнения/приёмки указанного решения N3 остаётся открытым.

## Локальная проверка

На текущей локальной ветке `codex/cg-018-policy-unicode`:

- Новые unit-тесты — **8 PASS, 0 FAIL, 0 SKIP**: pins, drift каждого поля
  профиля, non-NFC, неназначенный символ, одиночный surrogate/emoji, отсутствие
  мутации/утечки текста, malformed corpus, воспроизводимость и отказ от путей/URL.
- Прежние тесты v1-reader — **4/4**, привязки схем и source pin — **2/2**.
  Это чистые fixtures-тесты, не запуск DB/repository-набора.
- CLI — `baseline_match`: **3** снимка, **272** строки (включая ключи),
  invalid snapshots/non-NFC/unassigned/lone surrogate — **0**; оба pins совпали.
  Фактический профиль — Node **24.11.1**, ICU **77.1**, Unicode **16.0**.
- ESLint двух scripts, Prettier девяти изменённых/новых файлов и
  `git diff --check` — PASS. Проверены **114 относительных ссылок** семи
  Markdown-файлов, ошибок нет.

Использованы pnpm **10.15.0** и безопасный launcher без `.env`/ключей.
Первый запуск в Windows sandbox остановился внутри `tsx` на `uv_os_get_passwd`;
те же ограниченные offline-тесты успешно повторены вне sandbox, без подмены
toolchain. Полный `pnpm check`, Docker smoke, E2E, Expo, working DB, live AI,
сервер и deploy для этой ветки не выполнялись. Ничего не удалялось.
Эти результаты не закрывают N3 и не являются приёмкой R1.
