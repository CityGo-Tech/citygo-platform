# Сохранение подтверждённых телефонов

CityGo сохраняет нормализованный телефон после успешного SMS-подтверждения,
чтобы оператор мог вести клиентскую базу в админке. Новых флажков или шагов
подтверждения в пользовательском интерфейсе нет. Действующее согласие при
регистрации предусматривает обработку телефона, если пользователь привязывает
его к аккаунту. Это изменение не расширяет отдельный выбор email-рекламы на SMS.

## Хранение и неизменность доказательства

Миграция `0036_protected_phone_contacts.sql` добавляет nullable-поле
`phone_contact_bindings.protected_phone`. Исходный номер не записывается в SQL,
аудит, журналы ошибок, URL или контекст ИИ.

API шифрует телефон AES-256-GCM со случайным 12-байтовым nonce. HKDF-SHA256
выводит отдельный ключ шифрования из существующего `PHONE_VERIFICATION_SECRET`
с назначением хранения контактов. Секрет идентификации и его закреплённый
отпечаток не меняются; напрямую ключ HMAC для AES не используется. Формат `pc1`
включает идентификатор ключа, nonce, шифротекст и тег. AAD связывает запись с
исходным владельцем SMS-доказательства, HMAC номера и ID запроса кода.
При чтении проверяются тег, формат номера и совпадение его HMAC.

Зашифрованное значение создаётся в той же транзакции, что погашение кода,
подарок 500 ₽ и привязка телефона. Ошибка откатывает все эти действия. Повтор
подтверждения не переписывает контакт. Значение привязано к исходному
`phone_code`-доказательству и не меняется при операторской отвязке/передаче;
список показывает только действующую привязку активного аккаунта. История
привязок и постоянный запрет второго подарка по номеру сохраняются.

Для восстановления контактов из резервной копии нужен существующий секрет
телефона из закрытой конфигурации. Его нельзя заменять: он также обеспечивает
дедупликацию подарков. Миграция не восстанавливает телефоны старых аккаунтов
из HMAC и не обращается за ними к журналам SMS-провайдера. Накопление начинается
с новых успешных подтверждений после установки этого кода.

## Доступ в админке

Раздел «Клиентская база» загружается по явному действию super admin и показывает
аккаунт, email, подтверждённый телефон и дату проверки, по 50 контактов на
страницу. `GET /v1/admin/phone-contacts` повторно проверяет текущую сессию,
активность аккаунта, роль super admin и смену временного пароля под общим
security lock. Обычный admin и пользователь доступа не имеют.

Ответ имеет `Cache-Control: no-store`. Контакты не сохраняются в localStorage
или обычном профиле пользователя; при смене сессии, уходе со вкладки, скрытии
номеров или ошибке загрузки предыдущие номера убираются из интерфейса. Аудит
содержит актёра и факт просмотра страницы, без телефонов, шифротекста или OTP.

В ProstoSMS база абонентов не создаётся и не синхронизируется. Это изменение
не отправляет SMS, не запускает рассылки и не меняет тарифы или отправителя.
Существующие проверки номера, ограничения частоты, подарок 500 ₽, резерв 5 ₽,
три режима ИИ, тарифы и ЮKassa с чеками остаются прежними. Автодеплой выключен;
установка миграции 35 → 36 требует отдельного проверенного выпуска.
