## Для оператора

Это инструкции для согласованного целевого окружения, не разрешение запустить
все команды подряд. Сначала проверьте целевой сервер, версию, доступы и границы
расходов. Не копируйте production-секреты или пользовательские данные в тесты.

Начните с [руководства по серверу и CI/CD](operations/server-handbook.md):
топология, активные пути конфигураций, GitHub Secrets/Variables, стадии выпуска,
границы автообновления, бэкапы и безопасная диагностика.

Инструкции `release-*` описывают отдельные контролируемые шаги релиза. Входить
в них следует через операторский порядок, а не выбирать шаг по имени файла.
`cloudru-runtime` и `production` описывают первоначальный запуск, а
`backup-operations` — прежний ограниченный scheduler. Они не заменяют текущий
autodeploy и постоянные почасовые копии; повторно устанавливать их на работающей
ВМ не нужно.

## Что считать источником истины

- **Что выполняется сейчас:** код выбранного коммита и его тесты. Сводка —
  [статус проекта](project-status.md), но её дата важна.
- **Что должен делать продукт:** решения в `product/` и принятая спецификация
  CG-010. Кандидатный контракт не доказывает наличие runtime-функции.
- **Что делать дальше:** [план](roadmap.md), сохраняющий номера CG из исходной
  очереди от 14 сентября. Исторический план не отменяет поздние решения владельца.
- **Как безопасно выполнять операцию:** соответствующий runbook и текущие
  проверки целевого окружения. Старый успешный отчёт не заменяет свежую проверку.
- **Что развёрнуто:** подтверждённый SHA/digest релиза и проверка сервера, а не
  последняя ветка GitHub или открывающаяся главная страница.
  Пример проверяемой записи — [снимок 4 октября](operations/runtime-2026-10-04.md).

При изменении функции обновляйте её документацию и строку статуса в том же PR.
Не переписывайте исторические отчёты так, будто будущая работа уже выполнена.

## Короткий словарь

| Термин                | Простыми словами                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------------------ |
| R1                    | Первый ограниченный релиз: закрытый жилищный Web-пилот                                                 |
| CG-012 и другие CG    | Постоянные номера задач в очереди, не версии приложения                                                |
| Артефакт              | Сохранённый полезный результат: например, бриф или чеклист, а не просто сообщение                      |
| Контракт              | Проверяемая форма данных и правила обмена между частями приложения                                     |
| Ревизия               | Номер конкретного сохранённого состояния результата                                                    |
| Receipt / evidence    | Серверная запись подтверждения / проверяемое основание для действия; одного флага клиента недостаточно |
| Handoff               | Передача темы другой роли либо сохранение запроса помощи человека                                      |
| SSE / streaming       | Ответ поступает частями по мере генерации                                                              |
| Hold / ledger         | Временное удержание денег / журнал операций                                                            |
| Outbox                | События, записанные вместе с основной операцией для последующей надёжной доставки                      |
| Evals                 | Проверки поведения и качества AI на заданных сценариях                                                 |
| CI / deploy / runbook | Автоматические проверки / развёртывание версии / инструкция выполнения операции                        |

Наличие контракта, файла или зелёной проверки само по себе не означает, что
возможность включена у реальных пользователей.
