# Контракты и совместимость API — CG-008

Основание: main после PR #36, `d7f30f5`. Дата: 23 сентября 2026.
Границы продукта: [R1, Москва / 20 человек](../product/r1-pilot.md).

## Три независимые версии

- **Wire contract**: `X-CityGo-Contract-Version: 1` на запросах и ответах HTTP/SSE.
  Маршруты остаются `/v1/*`. Версия npm-пакета не является wire-версией.
- **Schema version**: `schemaVersion: 1` в кандидатных R1-ресурсах.
  Определяет структуру конкретного ресурса, не номер сохранения.
- **Revision**: положительное целое `revision` ресурса, ссылки `{ id, revision }`,
  `expectedVersion` в будущих командах и `currentVersion` при известном конфликте.
  Нельзя принимать новую ревизию за подтверждение старого результата.

## Матрица совместимости

| Клиент / сервер                                         | Поведение                                                                                                         |
| ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Старый клиент без заголовка → новый API                 | Поддерживаемый v1; прежние успешные JSON и `error`/SSE `message` сохранены                                        |
| Новый клиент → старый сервер без заголовка              | Поддерживаемый legacy v1, прежние runtime-схемы обязательны                                                       |
| Клиент с версией `1` → новый API                        | v1; дополнительные поля игнорируются читателем, известные проверяются                                             |
| Запрос с `0`, `2`, пустой строкой или списком версий    | HTTP 400 `CONTRACT_VERSION_UNSUPPORTED` до parsing/route handler, регистрации, logout, chat admission и model I/O |
| Новый клиент получает неподдерживаемый заголовок ответа | Тело отменяется, JSON/SSE не доставляется UI как успех, команды не повторяются                                    |
| Неизвестный, но корректно оформленный код ошибки v1     | Сохраняется как `ApiError.serverCode`; безопасный текст/HTTP status доступны для общего UX                        |

Отсутствующий заголовок допустим **только как legacy v1**, не означает принятие
любой будущей версии. Нельзя удалять поддержку headerless v1, обязательное поле,
переименовывать поле, менять его тип или расширять enum успешного ответа для
старого клиента без отдельного major/adaptation rollout. Новые error codes
допустимы: читатель имеет общий fallback. Неизвестный SSE event **не** игнорируется
как завершение: он остаётся ошибкой протокола из CG-004.

Обновление сначала выпускает совместимый API, затем Web/Expo. Перед удалением
старой версии нужны отдельные release-решение, проверка оставшихся клиентов,
инструкция обновления и совместимый отказ. При rollback этот клиент читает старые
ответы без metadata. Безопасность, ownership и согласия не ослабляются ради
совместимости. Заголовок не является авторизацией и не разрешает новые функции.

## Ошибки

HTTP сохраняет `{ error: безопасный текст }`. Новые поля:
`contractVersion`, `code`, серверный `requestId`, `retryable`, необязательный
`currentVersion`. SSE сохраняет `{ type: "error", message }` и те же metadata.
`X-Request-Id` совпадает с `requestId`; сервер создаёт его сам, не доверяет
одноимённому входящему заголовку. CORS раскрывает оба response headers.

`requestId` ошибки — корреляция HTTP-запроса, **не** ключ идемпотентности команды.
Существующий UUID сообщения и будущий `r1CommandSchema.requestId` имеют отдельную
семантику. Технические ошибки не включают тело запроса, SQL, токены или stack.

| Код                                                                                           | Действие клиента                                                                         |
| --------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `CONTRACT_VERSION_UNSUPPORTED`                                                                | Обновить клиент; после неизвестного ответа сначала проверить сохранённое состояние       |
| `VALIDATION_ERROR` / `PAYLOAD_TOO_LARGE` / `UNSUPPORTED_MEDIA_TYPE`                           | Исправить ввод/формат; не повторять неизменённую команду                                 |
| `UNAUTHENTICATED` / `FORBIDDEN` / `NOT_FOUND`                                                 | Текущие auth/ownership правила; чужой ресурс не раскрывается                             |
| `AI_POLICY_CHANGED` / `AI_CONSENT_REQUIRED`                                                   | Обновить сведения и получить явное согласие; не подставлять его автоматически            |
| `AI_QUOTA_EXHAUSTED` / `AI_BUDGET_EXHAUSTED`                                                  | Показать исчерпание соответствующего ограничения, не запускать retry/fallback            |
| `AI_BUDGET_UNAVAILABLE` / `AI_UNAVAILABLE`                                                    | Проверить доступность у администратора; не включать провайдера автоматически             |
| `REVISION_CONFLICT`                                                                           | Перечитать состояние; при наличии `currentVersion` не перезаписывать его старой командой |
| `CONFLICT` / `RATE_LIMITED` / `SERVICE_UNAVAILABLE` / `INTERNAL_ERROR` / `STREAM_INTERRUPTED` | Общий отказ, сохранить честный статус; перед повтором команды сверить результат          |
| `PLAN_STALE` / `EVIDENCE_REQUIRED` / `SOURCE_UNAVAILABLE`                                     | Зарезервированы для CG-009/012/014/011; пока не доказывают наличие этих проверок         |

`ApiError.code` остаётся транспортным кодом CG-004 (`http`, `timeout`,
`stream_error` и т. д.); не переиспользуется для серверных бизнес-кодов.
Metadata старых ответов может отсутствовать. `retryable: false` — консервативная
policy текущего сервера: автоматического повтора ни HTTP-команд, ни SSE нет.
Даже будущее `true` не заменит проверку идемпотентности и результата команды.

## Кандидатные R1-схемы

`packages/contracts/src/r1.ts` экспортирует runtime-схемы и производные типы:

| Схема                      | Что фиксирует                                                                               | Что остаётся следующей задачей                                      |
| -------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| `r1ProfileSchema`          | ID, owner, revision, данные анкеты без обязательного AI-согласия                            | Хранение/изменение версий; legacy профиль не изменён                |
| `r1PlanSchema`             | Версия профиля, список ссылок на квесты, active/superseded                                  | CG-009: backfill и принадлежность; CG-038: граф без циклов          |
| `r1QuestSchema`            | Plan/definition references, состояние, XP reward                                            | CG-009/014: транзакционная привязка и начисление                    |
| `r1ArtifactMetadataSchema` | Тип брифа/чеклиста, plan/quest, source versions, дата                                       | CG-010: обязательное содержимое и подтверждение; CG-012: сохранение |
| `r1RunSchema`              | Thread/request, plan/quest, agent, rejected/running/complete/interrupted/failed, результаты | CG-021: run/step/attempt, стоимость и исполнение                    |
| `r1SourceSchema`           | Синтетическая маркировка, URL, юрисдикция/scope, review/freshness metadata                  | CG-011: разрешение источника, актуальность, retrieval               |
| `r1HumanCaseSchema`        | Owner, необязательные plan/thread, оператор, статус, даты                                   | CG-015/016: независимый вход, переходы/права/аудит                  |

Это **не новые endpoints и не миграция существующих строк**. Сервер пока не
возвращает эти ресурсы. Метаданные артефакта без проверенного содержимого не
являются evidence и не дают XP. Состояния кандидатов не подтверждают выполненную
операцию, назначение человека или экспертную приёмку. До активации схем следующие
PR уточняют их вместе с fixtures и согласованными требованиями CG-010.

Читатели допускают добавочные поля, но не неизвестную версию/тип известного поля.
ID непрозрачны; revision — safe positive integer; списки ссылок ограничены 100,
дубли ID отклоняются. `r1PageRequestSchema`: limit 1…100, default 20, cursor до 512
символов; `r1CommandSchema`: явные schemaVersion, requestId, expectedVersion, без
неизвестных полей. Эти команды/пагинация не подключены к прежним маршрутам.
Серверные проверки владельца, связности, freshness и допустимых переходов всё
равно обязательны; успешная Zod-проверка формы не заменяет их.

## Проверка и ограничения

Положительные/отрицательные schema-тесты, Web/native transport fixtures,
интеграционные HTTP/SSE-тесты проверяют совместимость и новые коды. Полный CI
сохраняет прежний пользовательский путь. Новых live AI-вызовов, изменений ключей,
приглашений, денежных лимитов и production-настроек нет.

Основание выбора раннего hook и обработчиков ошибок:
[Fastify hooks](https://fastify.dev/docs/latest/Reference/Hooks/),
[Fastify error handler](https://fastify.dev/docs/latest/Reference/Server/#seterrorhandler).
