# Подготовка закрытого профиля памяти v16

Будущий профиль `citygo-api-web-postpay-memory-v1`, версия **16**, маркер
`CITYGO_AI_PROFILE=postpay-memory-v1` предназначен для проверенного кода со
схемой **47**. [Описание реализации](../implementation/assistant-long-context-memory.md).
Этот документ не запускает выпуск, не меняет сервер и не включает расходы.

## Контракт

Профиль v16 наследует v15 и фиксирует:

```json
{
  "LLM_MAX_INPUT_BYTES": "8388608",
  "AI_CONTEXT_STRATEGY": "model_window_memory_v1"
}
```

Профили v1–v15 не расширяются через окружение или добавление полей в старый
утверждённый JSON. Приватный файл и mount остаются привязаны к точному хешу;
он доступен только API. Ключи, магазин, чеки и состав получателей автоматически
не заменяются. В v16 остаются 4096 выходных токенов RouterAI, `medium` для
«Максимума», фактическое списание ×10 и плата «Минимума» 3 ₽ без удержания.

Контекстный planner использует до 100 пар и частные цитаты одного диалога,
а «Минимум» перед генерацией отправляет подходящий текст на `tokens/count`.
Прежнее уведомление с девятью парами нельзя считать описанием нового объёма.
До выпуска подготовить и утвердить новую редакцию сведений о контексте,
privacy/policy и catalog ID. Сохранённые согласия не переписываются задним
числом; совместимость клиента и необходимое явное действие пользователя
проверяются по принятому механизму новой редакции.

## Проверяемый порядок будущего перехода

1. Зафиксировать точные SHA/tree, три образа, миграцию 47, профиль v16,
   изменённый каталог и результаты обязательного CI/Container smoke.
   Целевые unit-тесты и PGlite не заменяют PostgreSQL-права и гонки.
2. Проверить сообщения 100 тыс. Unicode-символов на desktop/mobile, бюджет
   обеих моделей RouterAI, подсчёт GigaChat, неполную память и read-only preview.
   Предпросмотр не должен отправлять частные тексты провайдеру. Проверить
   смену сессии, старый клиент и отмену до/во время подсчёта.
   При ошибке счётчика/превышении окна после подсчёта проверить отказ без
   списания и автоматическое истечение существующей GigaChat lease. Не
   требовать немедленного следующего запроса «Минимума»: очередь намеренно
   сохраняет ограниченную lease, другие режимы остаются доступны.
3. Получить обычный допуск на точный выпуск по
   [процессу ручного postpay-выпуска](postpay-actual.md). Отдельно проверить
   доступность выбранного endpoint подсчёта и правила получателей; существование
   адаптера не доказывает доступ ключа или отсутствие платы у провайдера.
4. До переключения инвентаризировать pending-попытки старых execution keys.
   Сверять их только по исходной идентичности и старому профилю. Не повторять
   POST генерации, не подставлять новую конфигурацию и не записывать нулевую
   стоимость без доказательств. Неизвестная стоимость не блокирует весь чат.
5. Кратко закрыть доступ и допуск новых операций, дождаться текущих работ,
   создать свежую зашифрованную копию и проверить её восстановление. Применить
   миграцию **46 → 47** и проверенные grants: только `SELECT, INSERT` индекса
   для API, без доступа Worker. Проверить trigger и готовность схемы.
6. Подготовить закрытый API JSON v16 и отдельные hash-bound startup/finish
   разрешения. Успешное закрытое обновление само по себе не открывает ingress,
   AI, оплату, Worker, restart или автодеплой.
7. Новая стратегия и лимиты меняют execution keys/catalog. Подготовить явный
   CAS-переход бюджетных правил для новых execution, сохраняя счётчики и
   финансовые ограничения. Автоматического rekey, повышения потолков или
   включения ранее выключенного бюджета нет.
8. После проверки данных, схемы, профиля и совместимости последовательно
   восстановить ранее разрешённые доступ, AI и оплату. Зафиксировать фактические
   наблюдения по уже проверенной процедуре. Настоящие модельные проверки,
   если они нужны, выполнять отдельными согласованными попытками, не выдавая
   синтетический тест за подтверждение качества провайдера.

Исходная переписка остаётся источником истины. Память — ограниченный
перестраиваемый индекс; после миграции она может быть пустой или частичной,
а ленивое заполнение не объявляется завершённым без `indexComplete`.
Не обещать доступность всей истории или междиалоговую память.

В рамках подготовки этой функции не выполняются операции с рабочим сервером,
ключами, платежами, SMS или модельными расходами. Автодеплой не включается.
