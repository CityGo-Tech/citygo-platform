# Подготовка закрытого профиля контекста 64 КиБ

Новый профиль v15 `citygo-api-web-postpay-context64-v1` и маркер API
`CITYGO_AI_PROFILE=postpay-context64-v1` предназначены для отдельного будущего
выпуска на схеме 46. Они наследуют точный набор полей v14 и меняют только
`LLM_MAX_INPUT_BYTES`: `8192` → `65536` UTF-8 байт сериализованных инструкций,
профиля, выбранной истории и текущего вопроса. Профили v1–v14 сохраняют прежние
значения, ключи и условия проверки; v14 нельзя расширить через окружение.

Сохраняются максимум девять завершённых пар выбранного диалога и новый вопрос,
правила обработки незавершённых сообщений, `4096` выходных токенов RouterAI и
`medium` для рассуждений «Максимума». Это ограниченное увеличение контекста,
не постоянная память между диалогами, не неограниченное окно и не веб-поиск.
Лимит нового пользовательского вопроса и API-контракты не меняются.

Три режима, RouterAI ×10 и «Минимум» 3 ₽, списание после завершённого ответа без
денежного удержания, прежний магазин и чеки ЮKassa, email, телефон и подарок
сохраняются. Пределы расходов оператора не увеличиваются автоматически.
Больший вход может повысить реальную стоимость: прежний операторский потолок
не является гарантированным ограничением счёта провайдера.

## Проверка и будущий выпуск

1. Проверить синтетический диалог с работой, семьёй и жильём, границы размера,
   порядок сообщений и последний вопрос. Реальных переписок, ключей и документов
   в тестовой фикстуре нет; провайдерские запросы не нужны.
2. Выполнить обязательные проверки и Container smoke. Схема остаётся 46,
   миграций нет. Получить допуск на точный SHA и отдельное закрытое обновление
   профиля v15 по [действующему процессу](postpay-actual.md).
3. До смены профиля получить инвентаризацию неизвестных попыток v14 и сверить
   те из них, для которых ещё возможно доказательное GET-чтение. Сверка требует
   точного совпадения `execution_key`; после перехода на v15 старые pending-записи
   не должны автоматически переинтерпретироваться через новый execution.
   Неразрешённые случаи требуют отдельного решения и сохраняются в журнале,
   не блокируя новые диалоги. Не повторять POST модели и не записывать нулевую
   стоимость без доказательств; проверку идентичности не ослаблять.
4. Подготовить новый закрытый JSON API и отдельное startup-разрешение версии 15,
   привязанные к хешам. Mount доступен только API, не Web/Worker/migrator.
   Успешные `start`/`finish` сохраняют закрытый ingress и запрет Worker/restart;
   они не открывают доступ, AI, оплату или автодеплой.
5. Увеличение входного лимита создаёт новые execution keys и catalog ID.
   Утверждённые ранее правила бюджета не подходят: подготовить отдельный
   проверяемый CAS-переход правил для новых execution с сохранением счётчиков,
   выбранного режима и текущих финансовых ограничений. Автоматического rekey,
   повышения потолков и включения выключенного бюджета нет. При сохранении
   получателей, уведомления и числа сообщений consent policy ID не меняется;
   его фактическое совпадение проверяется при подготовке выпуска.

Этот документ описывает подготовленный код. Он не подтверждает обновление
сервера, качество живого ответа или право выполнить выпуск без допуска владельца.
