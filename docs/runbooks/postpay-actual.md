# Закрытый выпуск postpay_actual_v1

Профиль запуска v14 `citygo-api-web-postpay-actual-v1` предназначен только для
проверенного кода со схемой 46. Маркер контейнера — `CITYGO_AI_PROFILE=postpay-actual-v1`.
Это отдельная конфигурация; профили v1–v13 сохраняют прежние значения и точные
наборы ключей. Добавлять новые поля в уже утверждённый файл v13 нельзя.

## Контракт конфигурации

Закрытый JSON API содержит весь прежний набор v13 и ровно два дополнительных
фиксированных поля:

```json
{
  "AI_CUSTOMER_BILLING_MODE": "postpay_actual_v1",
  "AI_REQUEST_COST_LIMIT_MODE": "operator_ceiling"
}
```

Значения `AI_ASSISTANT_MODES=enabled`, `AI_CREDIT_MODE=routerai_citygo_10x`,
`AI_MINIMUM_FIXED_FEE=enabled` и прежние настройки email, телефона и фискальных
чеков остаются обязательными. `AI_CREDIT_RESERVATION_MODE=fixed5_overdraft`
сохраняется как совместимый транспортный параметр старого APK; в новом режиме
он не означает удержание 5 ₽ у пользователя. Admission записывает отдельную
идентичность попытки без денежного резерва; предел RouterAI рассчитывается из
доступного баланса, а окончательное списание опирается на подтверждённую
стоимость ×10. «Минимум» сохраняет плату 3 ₽ за успешный ответ.

JSON подключается одним закрытым read-only mount только к API. Параметры нового
биллинга запрещены в окружении контейнера, Web, Worker и migrator. Ключи,
получатели и точное содержимое файла остаются привязанными к SHA-256 отдельного
разрешения запуска; в Compose и журналы секреты не копируются.

## Порядок выпуска

1. Получить отдельное разрешение владельца на точный SHA кода, образы, миграции
   и новый профиль; прежние разрешения v13 не переиспользовать.
2. Пройти локальные/CI проверки, Container smoke и восстановление свежей
   зашифрованной резервной копии. Проверить inventory 46 миграций, 79 таблиц и
   23 последовательности; не удалять прежние записи или неизвестные списания.
3. Через действующий проверенный closed-release workflow связать SHA-256
   миграционного разрешения, закрытого JSON API и разрешения запуска v14.
   Переход до схемы 46 и API readiness должны завершиться успешно до открытия
   трафика. Не запускать SQL или контейнерные команды вручную из этого документа.
4. `start`/`finish` сохраняют закрытый ingress, запрет Worker и restart, проверку
   неизменности секретов, образов и сети. Успешный finish сам по себе не разрешает
   открытие доступа, AI-бюджета, платежей либо автодеплоя.
5. Отдельно проверить наблюдаемые текущие состояния и получить/применить
   разрешённые действия открытия. Ранее выключенный администратором AI-бюджет
   нельзя автоматически включать как побочный эффект обновления.

Неизвестная стоимость остаётся неизвестной. Reconciler выполняет ограниченные
GET-проверки исходной попытки, не создаёт повторный запрос модели и не заменяет
отсутствующий финальный чек нулевой стоимостью. История старых удержаний,
источников средств, телефонов и подарков сохраняется.

См. [процесс обновления](automatic-main-deployment.md) и
[локальные проверки](local-development.md). Этот документ описывает код и
порядок подготовки; он не является свидетельством выполненного выпуска.
