# Закрытая проверка мини-приложений CityGo

## Состояние

Локальные сценарии используют заглушки SDK, тестовые аккаунты и изолированные данные. Для прогона на телефоне предстоит подтвердить выделенных ботов Telegram и MAX, закрытый HTTPS-адрес с Web/API и отдельную базу. Реальная проверка внутри мессенджеров требует запуска из этих ботов на устройстве.

Подготовленные сценарии описаны в PR [#214 «Профиль, телефон и поддержка»](https://github.com/CityGo-Tech/citygo-platform/pull/214), [#215 «Тестовая оплата Stars»](https://github.com/CityGo-Tech/citygo-platform/pull/215) и [#216 «Тестовое пополнение MAX»](https://github.com/CityGo-Tech/citygo-platform/pull/216). Перед прогоном зафиксируйте точный SHA ветки и функции, которые в неё входят.

## Подготовка закрытой среды

1. Владелец утверждает отдельный HTTPS-хост, список тестировщиков и двух выделенных ботов. Ограничьте доступ в тестовой среде, в том числе по прямому URL. Тестовая БД, сессии и хранилище должны быть отделены от рабочего CityGo. Используйте вымышленные аккаунты и материалы.
2. Подключите URL `https://<test-host>/mini/telegram` к выделенному боту Telegram через BotFather. Проверьте кнопку в чате, затем прямую ссылку `https://t.me/<test-bot>/<short-name>?startapp=housing`. Для подключения `Main Mini App` используется ссылка `https://t.me/<test-bot>?startapp=housing`. Запустите также ссылку с `startapp=coordinator` и гостевой запуск без задачи. [Способы запуска Telegram](https://core.telegram.org/bots/webapps#implementing-mini-apps)
3. На платформе MAX для партнёров у выделенного бота укажите `https://<test-host>/mini/max` и проверьте кнопку в чате. Прямая ссылка для жилищного сценария имеет вид `https://max.ru/<test-bot>?startapp=housing`. Повторите запуск с `startapp=coordinator` и без значения `startapp`. [Подключение и диплинки MAX](https://dev.max.ru/docs/webapps/introduction)
4. Передайте токены выделенных ботов через хранилище секретов тестового API. Используйте `TELEGRAM_MINI_APP_BOT_TOKEN` и `MAX_MINI_APP_BOT_TOKEN`. Зафиксируйте только наличие настроек и имя среды. Для регистрации и восстановления понадобится тестовая почта с доступом к тестовым сообщениям. Проверки ИИ и SMS проводят с детерминированным провайдером и тестовой доставкой. [Проверка данных запуска](../implementation/mini-app-launch-verification.md) · [Вход и привязка](../implementation/mini-app-account-access.md)

На этапе закрытой приёмки платные ИИ-запросы в мини-приложениях, рабочие магазины, расход рабочего рублёвого баланса и акция 500 ₽ в MAX отключены. Все действия выполняются в выделенной среде.

## Прогон на устройствах

Запишите модель устройства, версию ОС и версию приложения. Для Android начните с Honor 200. iOS и браузерный запуск отмечайте отдельными прогонами. При блокировке в браузерном клиенте зафиксируйте точный источник встраивания и вынесите изменение политики iframe в отдельную задачу.

Гостевые действия не создают аккаунт и не вызывают ИИ, SMS или оплату. При отказе SDK есть понятный способ попробовать снова.                                                                                 |

Выход, отвязка и смена владельца отзывают затронутые сессии и убирают черновики предыдущего владельца.                                                           |

Отдельно локально прогоните `pnpm test:e2e` с нужными спецификациями из `e2e/`. Мобильный профиль Playwright использует Chromium и моделирует размеры экрана. Результат на конкретном клиенте Telegram или MAX фиксируется только после его запуска на устройстве.

## Платёжные сценарии

**Telegram Stars.** Локально запустите `pnpm test:e2e e2e/telegram-stars.spec.ts` из ветки PR #215. Здесь используются синтетический счёт и обновления Bot API. Для проверки нативной оплаты нужны отдельные учётная запись и бот в тестовой среде Telegram, тестовый транспорт Bot API и тестовый приём обновлений. По официальной инструкции вход в тестовую среду описан для iOS, Telegram Desktop и macOS. Наличие доступа на Android проверяется отдельно. При приёмке проверьте закрытие окна до оплаты, ожидание, успешное серверное событие, повтор события, `/paysupport` и полный возврат. Квитанцию и единицу учитывайте как результаты тестовой транзакции. [Тестовая среда Telegram](https://core.telegram.org/bots/webapps#using-bots-in-the-test-environment) · [Тестирование Stars](https://core.telegram.org/bots/payments-stars#testing-payments)

**MAX и ЮKassa.** Локально запустите `pnpm test:e2e:max-payments` из ветки PR #216. Этот процесс слушает loopback и использует PGlite, заглушку MAX Bridge и синтетический HTTP-транспорт. Для прогона на телефоне требуются подтверждённый доступ к отдельному тестовому магазину, отдельный адрес тестовых уведомлений и адаптер к тестовому магазину для закрытой среды. После создания заказа отдельно нажмите «Перейти к оплате». Проверьте отмену, возврат из платёжного окна без зачисления, обработку оплаты после закрытия мини-аппа, один приход и один возврат при повторе события. Независимый статус регистрации чека в тестовом магазине берите из подтверждённого ответа провайдера. [Тестирование ЮKassa](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing) · [MAX Bridge](https://dev.max.ru/docs/webapps/bridge/#window-webapp-openlink-url)

## Фиксация результата

- Укажите дату, SHA, платформу, модель, версию ОС и мессенджера, тип запуска и сценарий. Для каждого сценария запишите «прошёл», «сбой» или «не проверен» с причиной.
- Для операций фиксируйте время, последовательность статусов и обезличенный идентификатор тестовой операции. Снимки делайте только на вымышленных данных. Не сохраняйте токены, cookies, `initData`, коды, контакты, содержимое документов или несокращённые URL оплаты. Не прикладывайте полный сетевой дамп запуска.
- В итоговом отчёте отделите локальный прогон, проверку реального клиента и проверку тестового платёжного провайдера. Коммерческая активация и рабочий выпуск относятся к отдельному решению.
