# Суточный денежный резерв на аккаунт

> Решение владельца от 18 октября 2026 отменяет персональный суточный денежный
> лимит в новом продукте. При переходе нужен явный `userDailyLimitMicros: null`
> с актуальной ревизией и сохранением общих защитных бюджетов. Эта документационная
> правка не меняет настройки работающего сервера. См. [новый порядок](../implementation/citygo-billing-and-yookassa.md).

> Исторический технический ограничитель, не выбранный тариф. С 2026-09-27
> владелец выбрал **разовые** 500 ₽, затем пополнение. См. [разовый баланс](ai-credit.md).
> Инструкции ниже не означают ежедневную выдачу нового бесплатного бонуса.

Персональный лимит дополняет общий бюджет сервиса и лимиты количества запросов.
Он не включает провайдера, не выдаёт согласие пользователя и не увеличивает
общий бюджет. Ограничение действует на аккаунт CityGo, а не на физическое лицо:
несколько сессий одного аккаунта используют общий остаток, разные аккаунты — разные.

## Настройка

В Admin → бюджет AI поле «Лимит на аккаунт в сутки UTC» задаёт сумму в валюте
бюджета. Для 500 ₽ выберите бюджет в RUB и введите `500`.
API-поле `userDailyLimitMicros` для этой суммы равно `500000000`.
При валюте USD это поле означает доллары, а не рубли; конвертации нет.
Менять валюту бюджета после первого денежного резерва нельзя.

- Положительное значение ограничивает каждый аккаунт за текущие сутки.
- `0` запрещает новые денежные резервы для всех аккаунтов.
- Пустое поле (`null`) явно снимает только персональное ограничение.
- Отсутствующее поле в API сохраняет ранее установленный лимит.

Общий суточный и общий накопительный бюджеты остаются независимыми ограничениями.
Снижение персонального лимита ниже уже зарезервированной суммы допустимо:
остаток станет нулевым, история не изменится, новые попытки будут запрещены.

Сутки — календарные UTC: обновление в **00:00 UTC / 03:00 по Москве**.
Перезапуск приложения, новая сессия или новый чат не обнуляют денежную историю.
Повторная попытка обращения к модели также требует отдельного резерва.

## Резерв — не фактическое списание

Сумма считается по серверному журналу `ai_model_attempts`: складываются денежные
резервы данного аккаунта в текущей валюте за UTC-сутки. Уже существующие
оценённые попытки учитываются сразу; старые записи без денежной оценки остаются
неизвестными и не превращаются в нулевые расходы. Фактические списания провайдера
не сверяются этим механизмом, автоматического возврата резерва нет.

Каждый запрос резервирует установленный консервативный потолок попытки до
обращения к провайдеру. Проверка остатка и запись проходят в одной транзакции
под блокировками; параллельные запросы одного аккаунта не обходят ограничение.
Аккаунт определяется серверной сессией, а не переданным клиентом идентификатором.
Web показывает лимит, резерв и остаток, но окончательное решение принимает API.

Если потолок одной попытки выше персонального лимита, запрос будет отклонён
даже при нулевом использовании. Admin показывает предупреждение и не уменьшает
автоматически потолок, объём ответа или качество модели. В частности, лимит
500 ₽ несовместим с ранее использованным защитным резервом Astra около
1666,67 ₽ на попытку. Это ограничение нельзя обходить заниженной оценкой стоимости.

## Безопасное включение

1. Остановить выдачу новых платных запросов и дождаться завершения старых.
2. Применить миграцию `0007_ai_user_daily_budget.sql`. Она добавляет nullable-поле
   и индекс, не меняет бюджеты, историю, согласия или настройки провайдеров.
3. Обновить **все** экземпляры API: старый код не проверяет новый персональный
   лимит. `/ready` нового API требует миграции `0006` и `0007`.
4. В Admin сохранить 500 ₽ на аккаунт при RUB, сохранив согласованные общие
   бюджеты. Проверить предупреждение о потолке попытки и текущий остаток аккаунта.
5. Отдельно проверить обоснованность денежного потолка и внешние ограничения
   провайдера. Не включать платный режим, если эти гарантии не подтверждены.

Само наличие этого поля не гарантирует жёсткое ограничение фактического счёта
RouterAI: такая гарантия зависит от достоверного потолка стоимости и поведения
провайдера. Эта доработка не меняет параметры качества Astra, не удаляет OpenAI
или GigaChat и не разрешает новые платные проверки.
