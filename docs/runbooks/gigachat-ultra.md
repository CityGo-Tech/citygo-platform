# GigaChat Ultra: подготовка подключения

Проверено по документации 14 сентября 2026 года. Это подготовка конфигурации,
не подтверждение действительности ключа, доступности модели или разрешение
на использование в публичном сервисе.

## Точный профиль

| Параметр       | Значение                                                     |
| -------------- | ------------------------------------------------------------ |
| Модель         | `GigaChat-3-Ultra` (в кабинете может отображаться Ultra 3.5) |
| Scope          | `GIGACHAT_API_PERS`                                          |
| Chat endpoint  | `https://api.giga.chat/v1/chat/completions`                  |
| OAuth endpoint | `https://ngw.devices.sberbank.ru:9443/api/v2/oauth`          |
| Режим ответа   | `stream: true`, SSE                                          |

Текущий адаптер CityGo уже использует эти адреса. Для точного Ultra ID
несовместимые `GIGACHAT_API_B2B` и `GIGACHAT_API_CORP` отклоняются до сети.
Другие модели GigaChat и их scopes не меняются. Автоматической замены модели,
перехода на старый адрес или fallback к другому провайдеру нет.

По [документации Ultra](https://developers.sber.ru/docs/ru/gigachat/models/gigachat-3-ultra)
модель доступна физическим лицам во Freemium-режиме, но не на платных тарифах
физлиц или организаций. [Условия коммерческого использования](https://developers.sber.ru/docs/ru/gigachat/tariffs/commercial)
и [соглашение для физлиц, §2.4](https://developers.sber.ru/docs/ru/policies/gigachat-agreement/individuals)
ограничивают Freemium личным некоммерческим использованием. Наличие корпоративного
пространства или оплаченного пакета другой модели не подтверждает доступ к Ultra
и право включать её в коммерческий CityGo. Production-блокировка сохраняется.

## Ключ и Supabase

Нужен **исходный Authorization key** из кабинета GigaChat — Base64-строка без
префикса `Basic` или `Bearer`. `Client ID` сам по себе недостаточен. Колонка
`DIGEST SHA256` в Supabase Secrets содержит отпечатки, а не значения секретов:
их нельзя подставлять вместо ключа или scope.

Соответствие имён при прямом подключении:

- Секрет `GIGACHAT_AUTH_KEY` в прежней функции соответствует серверному
  `GIGACHAT_CREDENTIALS` CityGo **по назначению**, но его отпечаток не является ключом.
- `GIGACHAT_SCOPE` должен содержать буквальную строку `GIGACHAT_API_PERS`.
- Произвольный секрет с именем проекта не является GigaChat Authorization key
  без подтверждения его назначения.

Ключ вводится локально через маскированное поле и хранится в защищённом хранилище
сервера. Не помещайте его в чат, исходники, GitHub, браузерное хранилище или
`NEXT_PUBLIC_*`. Не извлекайте его через диагностическую Edge Function.
Не перевыпускайте ключ автоматически: это может повлиять на прежнюю прокси.

При прямом подключении Supabase не участвует в маршруте. Существующую функцию,
её клиентов и секреты нельзя молча заменять. Для отдельной прокси-интеграции
потребуются обязательная серверная авторизация, корректный streaming, ограничение
размера запроса и времени, безопасные ошибки и обновлённое согласие на получателей.
`verify_jwt=false` без обязательной проверки внутри функции недостаточен.
Необязательный `PROXY_TOKEN` не защищает функцию, если секрет не задан.

## Безопасная последовательность

1. Проверить право использования выбранного API-проекта и модели. Скриншот
   баланса не заменяет актуальную проверку доступа и не является рублёвым бюджетом.
2. Сохранить оригинальный ключ серверным способом. Сохранение не вызывает API,
   не выбирает GigaChat и не выдаёт согласие пользователя.
3. Подготовить отдельный закрытый стенд без производственной истории. Настроить
   точный model/scope; оставить OpenAI и RouterAI неизменными. Если используется
   дополнительный CA, брать его из проверенного официального источника и применять
   только к транспорту GigaChat. **TLS и проверку имени сервера не отключать.**
4. Проверить OAuth и доступность модели без генерации, затем согласовать отдельный
   ограниченный тест генерации. OAuth использует `Basic`, запросы к модели —
   короткоживущий `Bearer` access token. Не сохранять и не показывать этот токен.
5. Freemium допускает один одновременный запрос. Первую проверку выполнять
   последовательно и не запускать параллельно Playground или другой клиент
   того же API-аккаунта. Блокировка отдельного чата CityGo не является общей
   блокировкой аккаунта GigaChat во всех приложениях.
6. Сохранить контроль расходов/попыток CityGo и запрет автоматического fallback.
   Дневной денежный лимит CityGo, консервативный резерв попытки, бесплатные токены
   Ultra и оплаченные токены других моделей — разные величины.
   Не выдумывать нулевой тариф или обменный курс,
   не сбрасывать старые резервы ради новой модели.

Первичная конфигурация сохраняет существующие 1400 выходных токенов и 60 секунд.
Это не характеристика максимальных возможностей Ultra. Увеличение нужно
согласовать отдельно для GigaChat, не меняя общие настройки OpenAI и RouterAI.
Нормальное завершение требует `finish_reason: stop` и `[DONE]`; `length`, обрыв
или фильтрация не считаются завершённым ответом и не дают основания для XP.
