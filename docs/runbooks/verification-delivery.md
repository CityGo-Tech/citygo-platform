# Почта и SMS для CityGo: подготовка подключения

Актуальность выбора и публичных условий: **23 октября 2026**.
Это подготовленный код и порядок подключения, **не публично включённая
отправка**. Само изменение кода не создаёт кабинеты, договоры, подписки, DNS
или ключи. Отдельные разрешённые операторские действия описаны ниже.
Сервер не обновлялся, автодеплой не включался. PR #109 остаётся отдельной
зависимостью: его сохранённые проверки не доказывают этот новый код.

## Операторская подготовка Postbox

На 23 октября 2026 для CityGo отдельно подготовлены каталог без сети и
сервисный аккаунт с единственной ролью `postbox.sender`. В Postbox подтверждён
домен `ситиго.рф`: обе DKIM CNAME имеют `Ok`, общий статус — `Success`.
Разрешён только отправитель `no-reply@ситиго.рф`; для HTTPS API используется
его ASCII-запись `no-reply@xn--c1ajazlh.xn--p1ai`.

После отдельного разрешения владельца выпущен статический ключ этого
служебного аккаунта. Секрет хранится зашифрованным вне Git и OneDrive,
не в `.env.example`, документации или Web/Expo. Пути закрытого хранилища и
операционные доказательства не публикуются в репозитории.

В двух закрытых тестах по двум отдельным разрешениям владельца отправлено
по одному контрольному письму. Оба имеют в Postbox статус `Delivery`;
получение первого владелец также подтвердил снимком своего почтового ящика.
Исходные результаты и журналы использованных разрешений сохранены, ни одна
попытка не повторялась. Эти транспортные тесты не создавали аккаунты и не
подтверждали владение адресом: для регистрации всё равно нужен ввод кода.

Диагностическая попытка воспроизвела причину отказа адаптера: Postbox вернул
HTTP `200` с типом содержимого, отличным от `application/json`, и прежняя
проверка MIME отклонила ответ ещё до разбора тела. Контракт
[SendEmail](https://yandex.cloud/ru/docs/postbox/aws-compatible-api/api-ref/send-email)
определяет `200` и JSON с `MessageId`, но не фиксирует MIME ответа.
Адаптер исправлен: для любого MIME тело только разбирается как ограниченный
UTF-8 JSON, а не отображается или исполняется. Точный HTTPS endpoint, отсутствие
редиректов, статус `200`, таймаут, предел 64 КиБ и проверка `MessageId` сохранены.
Ошибки очистки потока больше не подменяют результат или санитизированный отказ.
Исправленная версия проверена локально; дополнительного реального письма
после исправления не отправляли и сервер не обновляли.

Это **не публичное включение регистрации**. Любая следующая контрольная
отправка требует нового разрешения владельца на свой адрес; неизвестный
результат/таймаут не разрешает повтор. Принятие письма API и его получение
во входящие проверяются раздельно.
Платные условия публичной отправки согласуются отдельно; бесплатный пакет
провайдера сам по себе не отключает последующее платное использование.

Перед серверным включением нужен новый закреплённый runtime-профиль:
действующие профили не принимают поля `EMAIL_*`/`POSTBOX_*`.
Нельзя дописывать их в прежний закрытый конфиг или обходить проверку состава
ключей. Новый профиль должен сохранить существующие AI/денежные настройки,
ограниченный доступ только API к секретам и запрет автодеплоя, пройти полные
проверки и отдельный безопасный выпуск. Локальный тест этого не заменяет.

### Подготовленный закрытый профиль v8

Для следующего отдельного выпуска подготовлен новый идентификатор
`citygo-api-web-routerai-citygo-10x-yookassa-live-cn-fiscal-overdraft-postbox-email-v1`
(версия разрешения запуска **8**). Его контейнерный маркер — тот же суффикс
без `citygo-api-web-`. Профили 1–7 и их точные наборы ключей не расширены.
Новый профиль наследует прежние модельные настройки, резерв **5 ₽ CityGo**,
списание фактической стоимости **×10**, боевую ЮKassa и выбранные чеки.

В нём закреплены `EMAIL_REGISTRATION_MODE=required`,
`EMAIL_DELIVERY_PROVIDER=yandex_postbox`, точный ASCII From
`no-reply@xn--c1ajazlh.xn--p1ai`, а телефон и SMS выключены. Только приватный
API JSON получает отдельный email HMAC-секрет, пару статических ключей Postbox
и положительные `EMAIL_SEND_DAILY_LIMIT` / `EMAIL_SEND_TOTAL_LIMIT`.
Это счётные квоты, не согласованный денежный бюджет. Публикуемая fixture содержит
лишь вымышленные ключи и не является разрешением отправлять письма.

Локальное закрытое хранилище шифруется DPAPI. Контейнерный runtime читает отдельный
приватный JSON через существующий read-only API mount: ciphertext DPAPI нельзя
подменить этим JSON или передать Web/Worker. Во всех mounted-профилях, включая
disabled без AI-маркера, запрещён ambient-ввод `EMAIL_*`, `POSTBOX_*`, `PHONE_*`
и `SMS_*`. Секреты не передаются в Compose environment, Web или Worker.

Профиль остаётся `CLOSED_ONLY`: standing-autodeploy его не принимает.
Само добавление профиля не обновляет сервер, не открывает регистрацию, не
разрешает публичные платные отправки и не включает автодеплой.
Перед выпуском нужны закреплённые SHA/образы, успешные проверки, свежая проверенная
копия и отдельные разрешения на миграции, API-конфиг, закрытый запуск и доступ.
Текущий набор исходников содержит миграции 26 и 27; выпуск с 25 должен учитывать
обе, не подменяя полный inventory выборочной миграцией. Email требует таблицы
миграции 26; наличие миграции 27 само по себе не включает телефон или подарок.

По [ценам Postbox](https://yandex.cloud/ru/docs/postbox/pricing) следующие
2 001–10 000 писем стоят 80,31666666 ₽ за тысячу с НДС. Принятое сервисом письмо
может тарифицироваться и без доставки. Бесплатный пакет не является жёстким
ограничителем расходов. Первоначальные [лимиты](https://yandex.cloud/ru/docs/postbox/concepts/limits)
сервиса также не равны тарифу или бюджету CityGo.

[Цены SMS.ru](https://sms.ru/price) зависят от оператора, категории и числа
сообщений. Публичные стартовые значения около 8,36–8,50 ₽ не являются
подтверждённой ценой CityGo. Собственные имена отправителя у четырёх крупных
операторов могут суммарно стоить около **10 080 ₽ в месяц** ещё до сообщений
и шаблонов. Поэтому платное брендированное имя автоматически не подключаем.
Нужно проверить, подходит ли доступное общее имя и какой именно тариф действует
для подтверждения телефона перед подарком. SMS оплачивает оператор сервиса,
не пользователь из своих 500 ₽ CityGo.

Решение владельца от 23 октября: **фиксированный общий месячный денежный
потолок SMS не задаётся**. Это не подключение платных подписок и не принятие
неизвестных абонентских сборов: применимый тариф и дополнительные платежи
проверяются перед активацией. Технические квоты ниже остаются защитой от
накрутки, а не ограничением роста аудитории или обещанием денежного потолка.

Рассмотренные альтернативы: [Unisender Go](https://go.unisender.ru/) и
[Mailganer SMTP](https://mailganer.com/price/smtp) для почты;
[SMSC](https://smsc.ru/tariffs/) и [SMS Aero](https://smsaero.ru/price/sms/)
для SMS. SMS.ru не объявляется самым дешёвым: окончательный выбор после
подтверждения тарифов кабинета. SMS Aero отдельно ограничивает дешёвую
[авторизационную категорию](https://smsaero.ru/support/sms-rassylka/auth-soobshheniya/)
для программ лояльности/бонусов; переносить чужую цену на наш сценарий нельзя.

## Что подготовлено в коде

- Postbox: фиксированный HTTPS endpoint `postbox.cloud.yandex.net`, SigV4,
  `ru-central1`/`ses`, статический сервисный ключ, фиксированный From и один
  получатель. Только текст с кодом, без контекста AI, трекинга и рекламы.
- SMS.ru: фиксированный HTTPS POST, ключ только в теле, один российский
  мобильный номер, короткий текст. Режим `test` возвращает **accepted=false**
  и не может допустить подтверждение телефона/подарок.
- У обоих адаптеров ограничены время и размер ответа, запрещены редиректы и
  автоматические повторные отправки. Ошибки не содержат OTP, получателя,
  ключей или сырого ответа провайдера. Неопределённый результат запроса не
  считается бесплатным: повторная отправка только по действию пользователя.
- Успешный API-ответ означает принятие сообщения, **не доставку и не проверку
  человека**. Право подтверждения появляется только при верном коде.
- Email: глобальные суточная UTC/суммарная квоты учитывают все допущенные
  отправки, включая неудачные. Существующие лимиты получателя/IP сохраняются.
- Телефон: короткие транзакции, действующая сессия, подтверждённая именно
  текущая почта, шестизначный OTP, TTL 10 минут, максимум 5 неверных попыток;
  60 секунд между отправками, 3/час на аккаунт и номер, 10/час на IP.
- Миграция `0027_phone_verification.sql`: ожидающие подтверждения, журнал
  отправок, закреплённая политика и однократные требования подарка.
  Начисление **500 ₽ CityGo = 500 000 000 micros** и погашение кода атомарны.
  Повтор успешного запроса возвращает прежнюю операцию, не новый подарок.
  Используются существующие подарочные лоты и механизм погашения долга.
- API/клиент подготовлены; экран телефона Web/Expo, подтверждённая сквозная
  регистрация с реальной почтой, подключение SMS и безопасный серверный
  выпуск — ещё не выполнены этим этапом.

Один подтверждённый номер — ограничение злоупотреблений, **не доказательство
«один человек»**: у человека бывает несколько SIM, номера переоформляются.
Новый аккаунт на уже использованный номер второго подарка не получает.
Старый бонус также не даёт получить ещё один. Платный баланс и возвраты от
этого не меняются; подтверждение почты само денег не начисляет.

### Подготовленный API телефона

Все четыре метода требуют действующую сессию. Записи также соблюдают
общие Origin/версию контракта и повторную авторизацию внутри транзакции БД.

| Метод                                 | Назначение                                                                  |
| ------------------------------------- | --------------------------------------------------------------------------- |
| `GET /v1/phone-verification/policy`   | `disabled` / `unavailable` / `required`; не доказательство права на подарок |
| `POST /v1/phone-verification/start`   | Нормализованный телефон → отправка и challenge/proof без OTP                |
| `POST /v1/phone-verification/resend`  | Тот же challenge/proof/телефон → новый код, старый больше не действует      |
| `POST /v1/phone-verification/confirm` | Телефон, challenge/proof и код → одна квитанция начисления                  |

Подтверждение текущей почты проверяется до допуска SMS и денег. Старые
аккаунты без такого доказательства получают 403; отдельного пути подтверждения
почты существующего аккаунта пока нет. При недоступном провайдере/непривязанной
политике телефонные записи закрыты с 503. OTP и proof не следует сохранять в
URL, local/sessionStorage, аналитике или логах будущего экрана телефона.

## Конфигурация и закрытые ключи

Все новые настройки API-only: не попадают в Web/Expo/build/worker. В
`.env.example` безопасные значения — оба транспорта выключены, квоты равны 0,
ключи пусты. В действующий серверный runtime-профиль новые поля **не добавлены**.

| Назначение  | Поля                                                                                             |
| ----------- | ------------------------------------------------------------------------------------------------ |
| Почта       | `EMAIL_REGISTRATION_MODE`, `EMAIL_REGISTRATION_SECRET`, `EMAIL_DELIVERY_PROVIDER=yandex_postbox` |
| Postbox     | `POSTBOX_ACCESS_KEY_ID`, `POSTBOX_SECRET_ACCESS_KEY`, `POSTBOX_FROM_EMAIL`                       |
| Квоты почты | `EMAIL_SEND_DAILY_LIMIT`, `EMAIL_SEND_TOTAL_LIMIT`                                               |
| Телефон     | `PHONE_VERIFICATION_MODE=sms_ru`, отдельный `PHONE_VERIFICATION_SECRET`                          |
| SMS.ru      | `SMS_RU_MODE=live`, `SMS_RU_API_ID`, согласованный `SMS_RU_FROM`                                 |
| Квоты SMS   | `PHONE_SMS_GLOBAL_DAILY_LIMIT`, `PHONE_SMS_GLOBAL_TOTAL_LIMIT`                                   |

Отправка телефона разрешается только при политике обязательной почты и
`AI_CREDIT_MODE=routerai_citygo_10x`. Email/phone HMAC-секреты — разные случайные
32 байта, не ключи провайдеров. Секрет телефона нельзя тихо заменить: иначе
потеряется соответствие уже использованных номеров. Ключ и нормализация
`e164-v1` вместе с лимитами должны однократно закрепляться оператором в
`phone_verification_control` через `configurePhoneVerification`. API-пользователь
БД читает эту политику, но **не может её настроить**. Автопривязки при старте
и административного HTTP endpoint для обхода нет. При отсутствии/несовпадении
привязки телефон недоступен; изменение требует отдельного плана миграции.

Квоты — количества допущенных запросов, **не денежный потолок счёта провайдера**.
До live нужны подтверждённый тариф и отдельное согласование платных условий;
автопополнение этим этапом не подключается. Тестовый режим SMS.ru — отдельная проверка адаптера, не способ
подтверждения настоящего номера. На публичном API тестовый успех запрещён.

## Порядок подключения после отдельного разрешения

1. **Почта:** создать изолированную папку Yandex Cloud для CityGo; определить
   адрес отправителя. Подтвердить домен/адрес по
   [инструкции Postbox](https://yandex.cloud/ru/docs/postbox/operations/send-email).
   Создать сервисный аккаунт с минимальной ролью
   [postbox.sender](https://yandex.cloud/ru/docs/postbox/security/) в этой папке,
   а не редактора всего облака. Ключ — только в закрытый серверный конфиг.
2. **DNS:** добавить выданные сервисом DKIM CNAME и корректный SPF по
   [инструкции](https://yandex.cloud/ru/docs/postbox/concepts/dns-records).
   Не создавать второй SPF и не заменять действующие записи вслепую.
   Согласовать DMARC; проверить доставку и спам на реальных контрольных ящиках.
3. **SMS:** до любых подписок получить в кабинете цену именно нашего OTP,
   доступное имя и необходимость шаблона; согласовать общий месячный бюджет.
   Выполнить [test=1](https://sms.ru/api/send), затем отдельно разрешённую
   настоящую отправку на свой номер. Статус 100 — принятие, не получение.
4. Согласовать уведомления пользователю, данные получателей и сроки хранения.
   Провайдер получает email/телефон и текст OTP, не историю разговоров.
   РФ-регион провайдера не обещает РФ-нахождение почтового ящика пользователя.
   Уточнить хранение/удаление у поставщиков, контакты поддержки и обработку
   отказов. Не заявлять юридическую готовность по одному включённому флагу.
5. Перед выпуском утвердить точный SHA, выполнить полные проверки, свежий
   backup/restore, миграцию и гранты в закрытом режиме. Закрепить телефонную
   политику отдельным операторским шагом. Не стирать журнал использованных
   номеров/квот; связанные reset-сценарии теперь отказывают безопасно.
6. Проверить настоящие письма/SMS, ошибочные/старые коды, resend, параллельные
   подтверждения и повтор операции. Только после приёмки включить выдачу
   подарка и законченный пользовательский экран. Существующий вход сохранять.
7. При сбое выключить новые телефонные операции; не объявлять пользователей
   подтверждёнными вручную, не повторять неизвестные отправки автоматически.
   Уже выданные подарки/историю не пересоздавать. Следить за ошибками и расходами.

Сроки хранения просроченных регистраций/кодов/IP-HMAC и последующая очистка
ещё требуют отдельного утверждения и реализации. Финансовые требования
подарка сохраняются для недопущения повторной выдачи; их удаление нельзя
смешивать с очисткой временных OTP. Подключение live до решения этих пунктов
этим документом не разрешается.

## Неизменяемые условия этого этапа

Резерв **5 ₽ CityGo**, фактическая стоимость AI **×10**, правило пополнения
**100 ₽ оплаты → 100 ₽ CityGo**, прежний магазин ЮKassa и его чеки сохраняются.
Новый магазин не создаётся, чеки не отключаются, автодеплой остаётся выключен.
Доставка OTP не меняет согласие пользователя на внешнюю обработку AI.
