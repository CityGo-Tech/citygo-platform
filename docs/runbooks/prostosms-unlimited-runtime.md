# ProstoSMS без общих лимитов отправки

Новый профиль **v11** подготовлен для решения владельца: не ограничивать SMS
общим числом за сутки или за всё время работы CityGo, пока провайдер принимает
запросы с оплаченным балансом. Этот документ описывает код и порядок выпуска;
само наличие профиля не означает его установку на сервере.

## Отдельная идентичность профиля

Серверный контроллер принимает только новую пару:

- версия разрешения запуска — `11`;
- профиль —
  `citygo-api-web-routerai-citygo-10x-yookassa-live-cn-fiscal-overdraft-postbox-email-prostosms-unlimited-v1`;
- маркер API-контейнера —
  `routerai-citygo-10x-yookassa-live-cn-fiscal-overdraft-postbox-email-prostosms-unlimited-v1`.

Оба поля `PHONE_SMS_GLOBAL_DAILY_LIMIT` и `PHONE_SMS_GLOBAL_TOTAL_LIMIT`
в закрытом API-конфиге должны быть точной строкой `unlimited`. Ни `0`, ни
`Infinity`, ни пропущенное значение не заменяют её. Профиль v11 требует оба
значения сразу; числовые квоты выбирают прежний профиль v10. Разрешения,
секреты и конфиги прежних профилей v1–v10 не приобретают новый смысл: v9 SMS.ru
и v10 ProstoSMS по-прежнему принимают только положительные конечные квоты.

Профиль остаётся `CLOSED_ONLY`: штатный автодеплой не получает права на такой
выпуск. API-ключ, отдельный секрет идентификации телефона и имя отправителя
находятся только в API-конфиге. Они не передаются Web, Worker, Git или Compose
environment. Резерв **5 ₽ CityGo**, списание фактической стоимости **×10**,
существующий боевой магазин ЮKassa, его фискальный профиль и Postbox сохраняются.

## Политика телефона и защита повторов

На уровне API строка `unlimited` преобразуется в `null` только для двух общих
счётчиков. `null` включается в закреплённую JSONB-политику и её fingerprint;
прежние числовые политики и их fingerprint не меняются. Миграция SQL для этих
двух значений не нужна. Уже закреплённую другую политику нельзя перезаписывать
через API или автоматически заменять при запуске.

Локальные ограничения злоупотреблений сохраняются: **3 отправки в час** на
аккаунт, **3 на номер**, **10 на IP**, пауза **60 секунд**; также остаются
существующее ограничение HTTP-запросов и максимум **5 попыток ввода кода**.
Подтверждённый email, действующая сессия, совпадение провайдера и отдельное
согласие пользователя нужны перед отправкой. Принятие SMS провайдером не
подтверждает номер и не выдаёт подарок.

Одна успешная проверка кода атомарно выдаёт **500 ₽ CityGo** и сохраняет claim
номера и аккаунта. Повтор возвращает прежнюю операцию; неизвестный результат
доставки не повторяется автоматически. Исчерпание баланса провайдера может
привести к отказу или неопределённому результату отправки. CityGo не обещает
жёсткий предел стоимости SMS и не пополняет провайдера автоматически. Пополнение
его кабинета, платные имена и изменение тарифов не следуют из профиля v11.

## Допуск выпуска и проверка

Изменились код API, разбор конфига и доверенный контроллер. Нужны полный прогон
проверок нового SHA, новые образы и новая версия контроллера; проверки старого
SHA и установленный контроллер с профилями до v10 не подтверждают поддержку v11. Обновление
текущей схемы 28 до 29 отдельно включает личный план и актуальные grants;
безлимитный режим SMS дополнительной таблицы не добавляет.

До открытого доступа оператор сохраняет свежую зашифрованную копию и проверяет
восстановление, выполняет закрытое обновление и явно привязывает постоянную
политику телефона. `/ready` подтверждает наличие таблиц, но не fingerprint
политики; дополнительно проверяется ответ политики телефона для авторизованного
пользователя без отправки SMS. Откат закрывает телефонный режим и сохраняет
claims, журнал отправок и подарочные проводки; он не возвращает использованное
право на подарок.
