# DeepSeek Pro через RouterAI: отдельный CN-профиль

Решение владельца от 19 октября 2026: использовать **DeepSeek Pro**, upstream
`deepseek`, фильтр страны `cn`; возможная обработка сообщений за пределами РФ
разрешена. **Flash не подключать.** Это заменяет прежнее требование `ru`, но не
подменяет согласие пользователя, одобрение точного публичного текста, бюджетное
правило, проверки выпуска или приёмку оплаты.

## Что именно закреплено

| Параметр           | Новый профиль                                                  |
| ------------------ | -------------------------------------------------------------- |
| Controller profile | `citygo-api-web-routerai-citygo-10x-yookassa-live-cn-v1`       |
| Startup approval   | **v5**, только для этого профиля                               |
| API marker         | `routerai-citygo-10x-yookassa-live-cn-v1`                      |
| Модель             | `deepseek/deepseek-v4-pro-0813`, не плавающий alias            |
| Upstream / country | `deepseek` / `cn`                                              |
| Reasoning          | `high`                                                         |
| Выход / вход       | `4096` токенов / `8192` UTF-8 байта сериализованного контекста |
| Таймаут            | `240000` мс                                                    |
| Тариф              | `routerai_citygo_10x`                                          |
| ЮKassa / чеки      | `live` / `npd_manual`                                          |

Модель не заменена более слабой. Уменьшены технические пределы одной попытки,
чтобы подготовить резерв, совместимый с небольшим пользовательским балансом.
При `high` часть выхода занимает reasoning: полезный ответ может оборваться по
лимиту. Это нужно проверить на вымышленных диалогах до открытия, а не обещать
одинаковое качество ответа при любом лимите.

Старые профили v1–v4 не переопределены: их `us`, `32768` и `64000` сохранены для
проверяемости прежних разрешений. Старый v4 JSON не принимается под новым marker
и наоборот. Standing autodeploy отвергает **оба** live-профиля: его resume открывает
доступ и не подходит для закрытой подготовки. Нужны отдельные target, образы,
controller generation и цепочка разрешений; прежние consumed approvals не подходят.

Новый API JSON имеет тот же закрытый список полей, ограничения ключей и изоляцию,
что [live v4](yookassa-routerai-live-profile.md), но другие точные значения выше.
Пример `deploy/fixtures/routerai-citygo-10x-yookassa-live-cn-profile.fixture.json`
содержит **только неработающие вымышленные credentials и policy ID**. Четыре
технические квоты в нём нулевые; бюджет, маршрут в БД и ingress он не включает.
Секреты предназначены только API, не Web/Worker/мигратору/backup.

## Получатели и уведомление

Публичный кандидат хранится в
[`routerai-pro-cn-policy.candidate.json`](../operations/routerai-pro-cn-policy.candidate.json).
В файле только модель, upstream, страна и текст, **нет ключей и approval**.
Офлайн `ai:policy:preview` показывает полный snapshot с описанием города, бюджета,
даты, состава семьи и до 20 завершённых сообщений, включая новый вопрос и прежние
ответы. Проверенный ID кандидата:

```text
5f3fdc3652b7fecfea85aa9d9c5f3067cd369d736accc3961bd0302698369ba3
```

Это результат вычисления для просмотра, **не одобренный production ID**. До
проверки и утверждения всего текста его нельзя устанавливать в рабочий mount.
Не копировать старый `us` ID и не вычислять согласие автоматически при старте.
Новый policy требует нового выбора маршрута, бюджетного execution rule и
согласия каждого пользователя перед отправкой его контекста. Старые согласия
и записи не удаляются.

Запрос CityGo содержит `only:["deepseek"]`, `allow_fallbacks:false`, `country:"cn"`.
Сам CityGo не повторяет его на Flash/другой модели. Но
[документация RouterAI](https://routerai.ru/docs/guides/overview/provider-selection)
предупреждает о резервных попытках вне `only`; поэтому нельзя обещать абсолютную
эксклюзивность upstream. Код страны также не доказывает место хранения или всю
цепочку обработки: `countries` может отражать штаб-квартиру. Независимая сверка
стоимости проверяет сообщённый RouterAI upstream и сохраняет резерв при несовпадении,
но не может отменить уже состоявшуюся передачу данных.

Адаптер также проверяет объявленный `model` в потоке до первого текста и при
дальнейшем изменении. Flash, alias или отсутствие первой identity вызывают отказ,
чтение отменяется без повтора; ID генерации сохраняется для сверки hold. Это
проверка декларации RouterAI, не независимое доказательство фактической модели.
Совместимость exact ID и первого служебного кадра остаётся пунктом живой приёмки.


и `reasoning` присутствуют, проверка exit 0. Это **метаданные**, не проверка

промпт не отправлялся. Перед настоящей приёмкой каталог нужно перечитать.

## Резерв и фактическое списание ×10

Снимок публичного endpoint-каталога на 04:43 МСК содержит переменные тарифы по
времени суток. Максимальные найденные ставки без cache-скидки: вход
`0.00020088316248`, выход `0.00060264948744` ₽/токен. Нельзя брать более дешёвую
строку другого провайдера или off-peak как потолок.

При предположениях «входных токенов не больше 8192 + H», «весь выход, включая
reasoning, не больше 4096» оценка:

```text
C = (8192 + H) × 0.00020088316248 + 4096 × 0.00060264948744 ₽
H = 4096 → C = 4.93690460110848 ₽
Предлагаемый резерв: 6 ₽ реальных = 60 ₽ CityGo
```

Это **условная оценка, не доказанный потолок счёта**. Байты JSON не равны prompt
токенам; `H=4096` — запас, не доказанная граница framing. Публичные
[параметры RouterAI](https://routerai.ru/docs/guides/overview/parameters) и
[нативный DeepSeek](https://api-docs.deepseek.com/api/create-chat-completion/)
не заменяют приёмку преобразования посредником и фактического общего выхода.
Цены могут измениться. Нельзя автоматически включать расходы на основании этой
формулы. Старые 64000/32768 дают уже около 32,60 ₽ реальных / 326,04 ₽ CityGo
при H=0 — это не подходящий резерв для пополнения 100 ₽ CityGo.

После проверок отдельная Admin-команда может утвердить exact новый execution и
`attemptCeilingMicros=6000000` в `routerai_balance`. Общий, суточный и личный
денежные лимиты — `null`, но пользовательский баланс и технические квоты остаются.
Профиль сам не записывает это правило. Остаток меньше 60 ₽ CityGo при таком
резерве блокирует новую попытку, даже если ответ мог бы стоить дешевле.

Финальное списание — не 60 ₽ и не оценка по токенам, а независимо подтверждённый
`total_cost` в RUB ×10, с точной десятичной арифметикой. Неизвестная/чужая стоимость
оставляет hold на сверке, а не превращает ответ в бесплатный. Подтверждённое
превышение ceiling дополнительно выключает общий бюджет до разбора оператором.
Потолок защищает журнал пользователя, но не
отменяет уже возникший внешний счёт. HTTP 402 не вызывает повтор/Flash.

## До установки и открытия

1. Получить настоящие CI для целевого SHA, построить образы и проверить новый
   контроллер. Локальный smoke не заменяет требуемый GitHub gate.
2. Утвердить полный новый snapshot. Подготовить отдельный защищённый API JSON,
   сохранив четыре нулевые квоты; не перезаписывать текущий mount.
3. Подготовить новую цепочку закрытого выпуска 21 → 22 с проверкой свежего backup.
   Текущий планировщик старых переходов нельзя механически запускать как 21 → 22.
4. Закрыто проверить маршрут, согласие, бюджетное правило и один вымышленный
   диалог с независимой сверкой стоимости/списания; только затем подобрать
   окончательные лимиты. На этом этапе такого вызова ещё не было.
5. Выполнить отдельно согласованный настоящий платёж 100 ₽ и полный возврат,
   сверить НПД-реестр и admission. Те же 100 ₽ нельзя одновременно потратить на
   AI и назвать полностью доступными к возврату. Подарок остаётся выключенным
   до подключения подтверждения телефона; тестовые деньги не финансируют real AI.
6. Проверить условия публичного допуска и открыть ingress отдельным действием.

Состояние установки и ограничения: [готовность запуска](../operations/launch-readiness-2026-10-19.md).

предыдущему коду, не является приёмкой v5. Эти проверки не равны GitHub CI,
успешному live-ответу или разрешению на выпуск.
