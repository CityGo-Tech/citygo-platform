# RouterAI: разовые 500 ₽ и списание без наценки

Владелец подтвердил 2026-09-27: 500 ₽ один раз после подтверждения участника
в Admin; списание по стоимости RouterAI без наценки. Пополнение **не подключено**.
Этот этап не разворачивает сервер, не выдаёт реальные бонусы и не разрешает расходы.

## Допуск

- `AI_CREDIT_MODE=disabled` — внутренний режим без списаний, значение по умолчанию.
  Ответ API: `chargingStatus: not_connected`.
- `AI_CREDIT_MODE=routerai_at_cost` — обязательный пользовательский баланс для
  модельных запросов. В этом режиме OpenAI/GigaChat отклоняются до сети: их тарифы
  не согласованы. Адаптеры сохранены; автоматического fallback нет.
- В production RouterAI запрещён без `routerai_at_cost`, даже с правильной policy.
  Режим меняется только согласованным выпуском всех API-реплик.
- Hard-disable, production-policy, пользовательское согласие и лимиты оператора
  независимы. Бюджет оператора должен быть в RUB. Конвертации валют нет.
- Потолок попытки должен помещаться в 500 ₽ и учитывать максимальный контекст,
  вывод и актуальную цену upstream. Бонус не подтверждает общий бюджет.
- Открытая регистрация не выдаёт бонус. Его подтверждает оператор по сверенному ID
  участника через Admin. Повтор не начисляет ещё 500 ₽; мультиаккаунты не распознаются.

## Путь запроса

1. Одна транзакция резервирует попытку, общий бюджет и пользовательский баланс.
   При недостатке денег резервы/счётчики попыток откатываются, модели запрос не идёт.
2. Резерв связан с точной попыткой и случайным UUID, передаваемым как `session_id`.
   Email и внутренний ID пользователя в этот идентификатор не включаются.
3. До входа в адаптер сохраняется отметка возможной отправки. ID из заголовка
   `X-Generation-Id`/SSE сохраняется до потребления ответа. Смена и повторное
   использование generation ID другой попыткой запрещены. Автоповтора модели нет.
4. Сохранение полного ответа и `response_complete` — одна транзакция. Затем один
   ограниченный по времени и размеру GET `/api/v1/generation?id=...` получает цену.
5. Проверяются ID, session ID, модель, upstream, `api=chat/completions`, `source=api`
   и отсутствие web search. Только `total_cost` становится стоимостью пользователя.
6. Исходная десятичная строка читается без binary-float умножения (JSON reviver
   source, Node ≥22.13). Учёт — целые микрорубли. Доли меньше 0,000001 ₽
   **отбрасываются в пользу пользователя**. Наценки и пересчёта по токенам нет.
7. Списание, освобождение неиспользованного остатка резерва и receipt атомарны.
   Повторная сверка не списывает второй раз. Общий бюджет оператора остаётся
   консервативным накопительным резервом: это не второй пользовательский кошелёк.

Формат проверен 2026-09-27 по [OpenAPI](https://routerai.ru/api/openapi.json),
[справочнику](https://routerai.ru/docs/reference) и
[описанию generation ID/стоимости](https://routerai.ru/docs/guides/overview/decisions/overview).
Стоимость в валюте баланса: интеграция рассчитана на рублёвый RouterAI-аккаунт.
Другой валютный аккаунт/новый контракт требуют отдельного адаптера.
Синтетические тесты не заменяют live-сверку с кабинетом.

## Ошибки и восстановление

- Неизвестная цена, обрыв и таймаут сохраняют резерв. Потолок не превращается
  в «фактическую стоимость», автоматического возврата/повторного вызова нет.
- Только доказанное отсутствие входа в адаптер разрешает освободить резерв.
  Отсутствие ID и рестарт процесса не являются таким доказательством.
- Web/Expo показывают остаток, резерв, списания и ID на сверке. Полный ответ
  остаётся доступен при недоступности сервиса стоимости.
- В Admin: ID участника + ID резерва + отдельное подтверждение. Метод
  `POST /v1/admin/ai/credit/reconcile`: `{userId,holdId,confirmReconcile:true}`.
  Суммы из клиента не принимаются. Требуются исходные модель/upstream/ключ
  RouterAI. Уже завершённая сверка не вызывает даже повторного GET.
- **Прерванные ответы, потерянные ID и сбой до сохранения полного ответа этим
  этапом автоматически не разрешаются.** Нужна ручная сверка оператора с RouterAI;
  инструмент подтверждённого разрешения спорных случаев — отдельная задача.
  Не очищать журнал и не выдавать второй бонус для обхода.
- Цена выше резерва: пользователь не уходит в минус, резерв остаётся, общий
  бюджет AI выключается и пишется аудит. Перед включением исправить потолок
  и разобрать попытку; расход провайдера не ограничивается сам по себе этим кодом.

## База и выпуск

Миграция `0009_ai_credit_charges.sql` добавляет связи попыток и receipts к `0008`.
Backfill, изменения старых миграций и автоматических бонусов нет. `/ready` требует
`0009`, необходимы обновлённые `deploy/postgres/grants.sql`. API может обновлять
служебную таблицу сверок, но не журнал операций; Worker не читает баланс, Backup читает.

Блокировки: users → account → charge; резервирование использует прежние
user/thread/attempt-budget блокировки, затем account того же уже заблокированного
пользователя. Сети в транзакциях нет. Удаление финансовых записей запрещено FK;
архивирование/анонимизация — отдельное решение.

Установка: разрешённый конкретный выпуск, backup, закрытие старых процессов,
миграции/ACL, одинаковый режим всех реплик. Старую версию, обходящую баланс,
нельзя возвращать для публичного AI. Текущий пилотный deployment-профиль оставлен
с `LLM_PROVIDER=disabled`. Отдельный [профиль RouterAI](routerai-deployment-profile.md)
теперь реализован, но для его применения ещё нужны одобрение выпуска, общий
бюджет/потолок, production-допуск и живой тест. Платежи — отдельно.

Проверки: изолированная БД и синтетический HTTP RouterAI; нулевой баланс до сети,
точные числа, однократность, параллельные запросы, атомарный rollback, чужие ID,
неизвестная стоимость, обрывы, дубликаты ID, превышение резерва, восстановление
и права Admin. CI дополнительно проверяет PostgreSQL, ограниченные роли,
миграцию с предыдущей схемы и backup/restore.
