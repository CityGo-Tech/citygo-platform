# Чистый запуск тестового CityGo

18 октября 2026 владелец разрешил удалить прежние тестовые аккаунты, переписки,
AI-попытки, финансовую историю и знания. Для этой операции предназначен отдельный
`FreshAccountReset`. Он не запускается при регистрации, миграции или старте API.
Прежний `ClosedAccountRestart` остаётся вариантом с сохранением расходов, но не
является выбранным сценарием чистого старта.

## Что готово в коде

Регистрация принимает пароль от 6 символов. Есть вход по email или логину,
роли `user`, `admin`, `super_admin`, смена пароля и отзыв сессий. Первый диалог
не требует анкеты. Временный `admin/admin` создаётся только оператором в закрытом
контуре; AI и администрирование запрещены до смены пароля.

Миграция `0014_citygo_credit.sql` расширяет существующий журнал баланса.
Режим API `AI_CREDIT_MODE=routerai_citygo_10x` резервирует сумму CityGo ×10 от
реального потолка, а списывает подтверждённую исходную стоимость RouterAI ×10.
Тариф сохраняется на попытке: старые операции не переоцениваются при перезапуске.
Неизвестная стоимость остаётся в резерве до сверки. Исходная квитанция хранит
реальные рубли, без умножения.

Внутренняя `topUpConfirmed` проводит подтверждённую оплату 1:1 и не начисляет
повторно один платёж. Миграция `0015_yookassa_orders.sql` добавляет отдельные
заказы тестовой ЮKassa. Авторизованный Web-клиент создаёт заказ, переходит на
страницу ЮKassa и явно запрашивает серверную сверку. Только проверенный серверный
GET успешного платежа разрешает проводку. Возврат по ссылке ничего не начисляет.
В production пополнение пока выключено; webhook, live и возвраты не реализованы.

Подарок 500 ₽ CityGo в новом режиме не выдаётся через старую админскую команду.
Сначала нужны подтверждение телефона и защита одного подарка на номер/аккаунт.
Провайдер подтверждения пока не выбран. Платный доступ не требует подарка.

## Проверка сервера перед поставкой

Read-only проверка 18 октября обнаружила версию PR #81 (`34f0295`), 12 миграций,
5 тестовых аккаунтов, 0 сообщений и 0 credit entries/charges. AI выключен;
серверный API-конфиг не содержит ключей моделей и настроек ЮKassa.
Также существует незавершённый marker операции backup от 7 октября.
Его нельзя удалять как способ обойти release gate: сначала разбор состояния,
сохранённых доказательств и отдельное завершение/прекращение операции.

До записи в автоматически развёртываемый main нужно остановить новые autodeploy,
проверить отсутствие активного выпуска и подготовить закрытое окно. Рабочие
ключи и адреса в Git или чат не копируются. Существующий профиль контейнера
`routerai-credit-v1` пока фиксирует legacy 1:1; для ×10 нужен проверенный профиль
поставки и согласованные pins, а не ручная подмена окружения контейнера.

## Полный сброс тестовых данных

1. Проверить точную целевую БД и установленную схему с миграцией 0015.
2. Закрыть ingress, остановить API/Worker и запретить их новые запуски.
   Завершить служебную pending-операцию по её процедуре, не стирать её маркер.
3. Создать проверенную резервную копию и сохранить отпечаток квитанции.
4. Передать ограниченному отдельному процессу оператора
   `CITYGO_ACCOUNT_DATABASE_URL`, `NODE_ENV` и ожидаемую цель без credentials.
5. Выполнить dry-run `dist/account-maintenance.js --fresh-start` с
   `--expected-target`, `--expected-environment`, `--expect-users=N` и
   `--maintenance-confirmed`. Проверить blockers и `snapshotFingerprint`.
6. Только для этого снимка добавить `--apply --erase-test-history`,
   `--expected-snapshot=SHA256`, `--backup-receipt-sha256=SHA256`,
   `--services-stopped-confirmed` и `CITYGO_ACCOUNT_BOOTSTRAP_CLOSED=true`.
   Флаги фиксируют заявления оператора, не останавливают сервисы сами.

В одной транзакции очищается фиксированный список таблиц без `CASCADE` и без
сброса sequences. Удаляются старые аккаунты, сессии, сообщения, профили, планы,
попытки, балансы, пополнения, аудит и `knowledge_sources`. Сохраняются схема,
миграционный журнал, grants, каталог квестов и маршрутизация. Операторский бюджет
выключается, счётчики очищаются, персональный суточный денежный потолок становится
`null`. Новый администратор и одноразовая квитанция создаются атомарно.

Квитанция содержит `accountingPreserved=false`, `knowledgeEmpty=true`,
`publicIngressMayOpen=false`. Внешние объекты и старые backups этой командой не
удаляются. При неизвестном результате commit нельзя повторять сброс наугад.

## Условия открытия доступа

- Через закрытый доступ сменить пароль первого администратора; проверить роли,
  вход, регистрацию, отзыв прежних сессий и запуск разговора без анкеты.
- Подключить серверный RouterAI, точную модель, согласие получателя и денежный
  бюджет. Выполнить один контролируемый живой запрос и сверить ответ/квитанцию/×10.
- Подключить API существующей ЮKassa. Хранить отдельный заказ аккаунта и проверять
  платёж через серверный API: магазин, сумма, валюта, режим и успешный статус.
  Возврат со страницы оплаты и тело webhook сами по себе не начисляют баланс.
  [Процесс платежа ЮKassa](https://yookassa.ru/developers/payment-acceptance/getting-started/payment-process).
- Принять настройки чеков/возвратов и пройти test, затем отдельно включить live.
- Подключить подтверждение телефона перед подарком либо оставить подарок выключенным.

База знаний начинается пустой. Offline-поиск и контракты уже подготовлены;
сохранение проверенных кандидатов и ограниченный research gateway — следующая
поставка. Обычный ответ модели не считается проведённым интернет-исследованием.
Личная переписка не публикуется в общей базе.

## Подключение тестовой ЮKassa

Тестовый магазин отделён от действующего магазина владельца. Ключ хранится вне
Git, OneDrive и клиентских сборок; в репозитории есть только имена настроек.
Проверка API-ключа выполняется чтением списка платежей, без создания настоящих
платежей и без перевыпуска ключа действующего магазина.

Для отдельного тестового API нужны `YOOKASSA_MODE=test`, `YOOKASSA_SHOP_ID`,
`YOOKASSA_SECRET_KEY` с префиксом `test_`, `LLM_PROVIDER=disabled`,
`AI_CREDIT_MODE=routerai_citygo_10x` и фиксированный HTTPS `WEB_ORIGIN`.
`NODE_ENV=production` не допускается. Используйте отдельную одноразовую БД,
а не рабочую БД пилота. Идентификатор магазина и ключ передаются только API.
В режиме `disabled` маршруты не вызывают ЮKassa, а кнопка пополнения скрыта.

Проверяемый сценарий:

1. Зарегистрировать вымышленный аккаунт и проверить нулевой баланс.
2. Создать тестовый платёж на 100 ₽. До оплаты баланс остаётся нулевым.
3. Использовать только [тестовые данные ЮKassa](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing),
   не настоящую карту. Тестовый магазин не переводит реальные деньги.
4. Нажать «Проверить тестовый платёж». Сервер проверяет сохранённые payment ID,
   owner, магазин, metadata заказа, точную сумму RUB, `test=true`,
   `status=succeeded`, `paid=true` и отсутствие возвращённой суммы.
5. Проверить начисление 100 ₽ CityGo, затем повторить сверку. Должна остаться
   одна проводка и тот же баланс. Другой аккаунт не должен видеть этот заказ.

При неизвестном результате создания сохраняйте прежний request ID. После
23 часов автоматический повтор создания запрещён: заказ требует ручной сверки.
Новый UUID не является способом исправить неизвестный результат платежа.

Тестовые зачисления нельзя переносить в рабочую БД или использовать для реальных
AI-запросов. БД сохраняет взаимоисключающие признаки тестовых платежей и допуска
реального AI. Их проверяют при старте API, при каждой попытке AI и при платёжной
проводке под общей блокировкой. Перезапуск с другим конфигом и другая реплика
не снимают запрет. Снять признак можно только полным закрытым сбросом, когда
аккаунты, попытки и платежи удалены, а бюджет выключен. Вариант перезапуска,
сохраняющий расходы, не снимает эту изоляцию.

До live отдельно потребуются чеки, условия оплаты, возвраты,
подтверждённая обработка уведомлений и разрешённое включение настоящего магазина.
Отдельный тестовый магазин и проверенный ключ не означают готовность публичного
сервиса принимать оплату.

- DB: 167 успешных тестов, 24 opt-in PostgreSQL пропущены в обычном запуске.
- Отдельный временный PostgreSQL 17: 25/25, включая настоящие гонки,
  изоляцию test/AI, пополнения, полный сброс и runtime grants; контейнер удалён.
- API: 277 успешных тестов, 1 PostgreSQL-only пропущен.
- Contracts: 104/104; API client: 39/39; config: 14/14.
- Web: 6/6 mocked browser-проверок на desktop и mobile; два helper-теста.
- Изоляция окружения: 17/17 применимых проверок, один Linux-only пропущен
  на Windows. Проверки завершения процессов выполнены вне ограниченного sandbox.
- API/DB/Web builds, typecheck API/Web/Mobile, lint изменённых пакетов,
  форматирование и `git diff --check` прошли. Шаблон `.env.example` не является
  форматируемым исходным кодом и в Prettier не передаётся.

Модели и платёжные подтверждения в автоматических тестах синтетические. Отдельно
проверен доступ к реальному API тестового магазина чтением списка платежей;
ключ сохранён в закрытой локальной конфигурации. Это не доказательство прохождения
оплаты. Настоящий платёж, SMS, живой AI и полный образ Docker в локальный набор
не входят. Тестовые пополнения нельзя использовать для финансирования реальных
запросов или переносить в live-баланс.
