# Серверный профиль RouterAI с разовым балансом

Код позволяет выбрать отдельный профиль `citygo-api-web-routerai-credit-v1`
через контроллер выпуска. **Наличие профиля не означает развёртывание, одобрение
передачи данных или разрешение расходов.** Базовый `compose.pilot.yml` и старые
startup approvals v1 по-прежнему запускают `LLM_PROVIDER=disabled`.

## До выпуска

1. Проверить зелёные `main` CI/container smoke и выпустить конкретные приватные
   образы. Не подменять source SHA/digest и не разворачивать `latest`.
2. Утвердить [публичную политику получателя](routerai-production.md). Выполнить
   `pnpm ai:policy:preview` только для публичных настроек, проверить весь текст
   и его ID. Не получать одобрение автоматически из неизвестного config.
3. Отдельно согласовать общий дневной/суммарный бюджет оператора и потолок одной
   попытки в RUB. Разовые 500 ₽ участнику — не общий бюджет владельца. Значения
   хранятся в БД через существующий Admin, не начисляются профилем выпуска.
4. Проверить существующий аккаунт администратора и его **числовой** ID.
   Профиль не создаёт аккаунт, не выдаёт бонус и не подменяет пользовательское согласие.
5. Подготовить **новый** защищённый API JSON вне Git/bundle, с локальным вводом ключа.
   Не менять файл, уже смонтированный работающим процессом. Пароль БД — для роли
   `citygo_api`, не администратора PostgreSQL. OpenAI/GigaChat и их старые ключи
   сохраняются отдельно; в этот профиль их не переносить, fallback отсутствует.

## Точные поля API JSON

Все поля обязательны, все значения — строки. Неизвестные поля запрещены.
Общий размер файла ≤16 KiB, строки без управляющих символов и внешних пробелов.

| Поля                                                               | Значение                                                                       |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| `DATABASE_URL`                                                     | Существующий секрет роли `citygo_api`, хост `postgres:5432`, БД `citygo_pilot` |
| `ADMIN_USER_IDS`                                                   | От 1 до 20 разных положительных числовых ID через запятую, без пробелов        |
| `ROUTERAI_API_KEY`                                                 | Только ключ рублёвого RouterAI-аккаунта, не в чат/Git                          |
| `ROUTERAI_DATA_NOTICE`                                             | Утверждённое публичное уведомление, до 4000 UTF-16 единиц                      |
| `ROUTERAI_PRODUCTION_POLICY_ID`                                    | Независимо утверждённый ID точного snapshot, 64 lowercase hex                  |
| `AI_CREDIT_MODE`                                                   | `routerai_at_cost`                                                             |
| `ROUTERAI_MODEL`                                                   | `deepseek/deepseek-v4-pro-0813`                                                |
| `ROUTERAI_UPSTREAM`, `ROUTERAI_COUNTRY`                            | `deepseek`, `us` — метаданные маршрута, не доказательство региона хранения     |
| `ROUTERAI_REASONING_EFFORT`                                        | `high`                                                                         |
| `ROUTERAI_MAX_OUTPUT_TOKENS`                                       | `32768`                                                                        |
| `ROUTERAI_REQUEST_TIMEOUT_MS`                                      | `240000`                                                                       |
| `LLM_MAX_INPUT_BYTES`                                              | `64000`                                                                        |
| `LLM_USER_DAILY_REQUEST_LIMIT`, `LLM_USER_DAILY_ATTEMPT_LIMIT`     | Явно выбранные целые 0–10000; прежний ориентир `20`                            |
| `LLM_GLOBAL_DAILY_REQUEST_LIMIT`, `LLM_GLOBAL_DAILY_ATTEMPT_LIMIT` | Явно выбранные целые 0–1000000; прежний ориентир `200`                         |

Суточные счётчики запросов и попыток — не деньги. Нулевые значения закрывают
модельные вызовы. Не менять закреплённые дневные лимиты между репликами.
Шаблон в `deploy/fixtures` — **только тестовый**, с нерабочим ключом и вымышленной
политикой; копировать его на сервер как рабочую конфигурацию нельзя.

## Одобрение и закрытый выпуск

Startup approval v2 имеет те же поля, что v1, но точные значения:

- `version: 2`;
- `profile: citygo-api-web-routerai-credit-v1`;
- `api_secret_sha256` — hash точных байтов отдельно проверенного нового API JSON;
- `allow_start: true`, `allow_traffic: false` — доступ пользователям ещё закрыт.

V1 не разрешает этот профиль; v2 не является wildcard. Полная цепочка прежняя:
preparation → migration → startup → finish, каждый approval привязан к предыдущему.
Для плана/проверки/установки используется [существующий операторский CLI](release-operator.md),
а не самостоятельный `docker compose up` с обходом проверок. Вывод `plan/verify`
показывает выбранный профиль, но не ключ/текст настроек.

Контроллер сам добавляет контейнеру `CITYGO_AI_PROFILE=routerai-credit-v1` и
`LLM_PROVIDER=routerai`. Остальное читается только из API mount. Web, Worker,
мигратор и backup не получают ключ; в Compose/receipts нет значений API JSON.
Не добавлять эту настройку вручную в окружение остальных сервисов.

Миграции и ACL, включая `0009`, выполняются перед запуском. API при старте
проверяет соответствие policy ID публичному snapshot; неверный ID закрывает запуск,
но не откатывает уже совершённые миграции. Поэтому публичный preview проверяется
**заранее**. Health-проверки выполняют только `/ready` и неавторизованные маршруты;
генерация, регистрация и денежные операции в них отсутствуют.

Finish и восстановление незавершённого commit сохраняют тот же профиль/секрет/hash.
Открытие ingress, допуск Worker и автоматический restart не разрешаются этим
approval. Базовая policy `llmProvider: disabled` в candidate manifest описывает
профиль по умолчанию, не является одобрением AI: исключение возможно только через
отдельный проверенный startup approval v2, привязанный к точному выпуску.

## После закрытого запуска

Проверить выбор RouterAI, конкретную политику, бюджет и администратора. Сначала
один отдельно разрешённый live-тест на вымышленных данных: stream, сохранение,
точная стоимость в кабинете и балансе, аварийное выключение бюджета. Не считать
синтетические проверки подтверждением реального ключа или доступности upstream.
Затем отдельно разрешить открытие доступа и подтверждать разовый бонус участникам.
Пополнение и автоматическое разрешение спорных прерванных списаний не включены.

Аварийная остановка новых расходов — выключение бюджета/маршрута в Admin.
Возврат к полностью отключённому AI — согласованный выпуск disabled-профиля с новым
API JSON только для БД/администратора; не очищать историю, резервы или approvals.

## Проверки

Строгие поля и версии, numeric admin IDs, подмена настроек/секрета до остановки,
полная цепочка finish/recovery на синтетических approvals, изоляция окружений.
Container smoke запускает настоящий production API с тестовым ключом в **internal**
сети Docker без выхода к моделям. Проверяются readiness/auth, выключенный бюджет,
нулевые попытки и бонусы. Это не live-тест RouterAI и не разрешение сервера.
