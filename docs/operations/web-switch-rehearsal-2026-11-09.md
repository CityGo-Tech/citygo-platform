этой записью. Новый CI workflow проверяет новый механизм отдельно.

## Что показала транспортная репетиция

Две копии одного готового production Next-образа с OCI revision
`42ecf835ea8c7f1488d70453e203c1c3149e2f92` работали с TLS Nginx и синтетическим
HTTP API. Проверены молчащий более 35 с SSE, незаконченный буферизуемый POST
через HUP с production `client_body_timeout 15s`, новое поколение workers и
новый upstream, завершение старых workers перед SIGTERM старого Web, exit 0
без OOM, доступность 44 прежних Next-файлов из архива. Синтетические счётчики
остались равны одному dispatch/debit/message; сессия не потерялась.

Это не настоящая финансовая транзакция, не тест PostgreSQL, не смена двух
различных версий и не запуск production `Host`-адаптера. Протокол контроллера
проверен отдельно с fake adapter. До применения нужен отдельный bootstrap и
сквозная репетиция установленного контроллера на изолированном Linux-стенде с
двумя различными совместимыми релизами.

Ранний более строгий прогон `81ec102b8725` зафиксировал один `socket hang up`.
Тогда ещё не было разбивки по виду/фазе/повторному использованию соединения,
поэтому причина не доказана. Результат сохранён, повторные запросы для сокрытия
ошибки не добавлены. Три последующих прогона дали 2332 пробы без ошибок с
расширенной диагностикой. Они не доказывают устранение первоначального сбоя.
Случай остаётся ограничением при приёмке; PR сохраняется черновиком.
